# Day 4 workshop template: checklist

The participant template repository that learners fork before Day 4. The
Day 4 pages (11a, Blocks 4–10) assume exactly this layout. Quarto ignores this
folder, so this file is not published.

## `.claude/settings.json`

The deny list protects specific files rather than whole folders, so the
agent can still write `scripts/01_clean.R` and `data/derived/` in Block 7,
and `scripts/functions/summary_functions.R` and
`tests/test_summary_functions.R` in Block 9.

```json
{
  "permissions": {
    "deny": [
      "Edit(/data/raw/**)",
      "Edit(/docs/data_note.md)",
      "Edit(/docs/codebook.csv)",
      "Edit(/scripts/02_validate.R)",
      "Edit(/scripts/03_audit_cleaning.R)",
      "Edit(/scripts/functions/validate_voles.R)",
      "Edit(/tests/fixtures/**)",
      "Edit(/tests/make_reference.R)",
      "Edit(/tests/test_cleaning.R)",
      "Edit(/.github/**)",
      "Edit(/.claude/**)",
      "Edit(/.posit/**)",
      "Edit(/hooks/**)",
      "Read(/.Renviron)",
      "Read(/.env)"
    ]
  }
}
```

## Before each run of the course

- [ ] Fork the template on a participant-type account and run Blocks 4–10
      end to end with Claude Code.
- [ ] In Claude Code, `/permissions` lists all 15 rules.
- [ ] The agent is refused when it tries to edit `data/raw/voles_raw.csv`,
      and allowed to write `scripts/01_clean.R`.
- [ ] `renv::restore()` succeeds on a clean machine.
- [ ] The shipped scripts' paths match the pages (`04_load_data.R`,
      `05_analysis.R`).
