# Block 3: the house theme
theme_project <- function(base_size = 12) {
  theme_minimal(base_size = base_size) +
    theme(
      panel.grid.minor = element_blank(),
      axis.title = element_text(face = "bold"),
      plot.title = element_text(face = "bold", size = rel(1.1)),
      plot.subtitle = element_text(colour = "grey40"),
      legend.position = "bottom",
      plot.background = element_rect(fill = "white", colour = NA),
      strip.text = element_text(face = "bold")
    )
}

The base ggplot2 grammar covers most chart types but makes several common visualisation tasks awkward. The extension packages below fill the gaps:

  • ggdist for distributional plots (raincloud, half-eye, point-interval); this is how you put “show the raw data wherever sample size permits” from Block 2 into practice.

  • colorspace and colorBlindness for palettes and accessibility checking; these put the encoding hierarchy and the accessibility principle from Block 1 into practice.

  • ggrepel and ggtext for direct labelling and rich text; these are the tools for the direct labelling and highlighting techniques in the audience table (Block 2).

  • patchwork for multi-panel composition, the natural alternative to facet_wrap() when subplots differ in chart type rather than data subset.

Statistical annotation (significance brackets, p-value labels on figures) is not covered in this workshop. The principled approach is to fit a model with emmeans or equivalent and use ggpubr::stat_pvalue_manual() to render the contrasts. In a half-day workshop on visualisation principles, we leave statistical annotation to the wider statistical training in your programme.

Each segment is short: a problem and a worked example to run along with us (the In your own time tasks are for after the session). Keep moving, because the block ends with a capstone exercise: recreating a published-style figure from scratch, on data you have not seen. There is a bonus after that: making a multi-panel figure interactive.

Distributions with ggdist

The default way to summarise a continuous variable across groups is a boxplot. A boxplot is informative but lossy: it shows quartiles and outliers but conceals the shape of the underlying distribution. Bimodality, skew, and gaps in the data all vanish.

The raincloud plot (Allen et al., 2021) addresses this by combining three layers: a half-density (the “cloud”) to show distribution shape, a slim boxplot for summary statistics, and jittered points (the “rain”) for the raw data. ggdist::stat_halfeye() provides the cloud half.

penguins_complete |> 
  ggplot(aes(x = species, y = body_mass_g, fill = species, colour = species)) +
  ggdist::stat_halfeye(
    adjust = 0.5,
    justification = -0.2,
    .width = 0,
    point_colour = NA,
    alpha = 0.8
  ) +
  geom_boxplot(
    width = 0.12,
    outlier.shape = NA,
    alpha = 0.5,
    linewidth = 0.4,
    colour = "grey20"
  ) +
  geom_jitter(width = 0.08, alpha = 0.4, size = 1.2) +
  colorspace::scale_fill_discrete_qualitative(palette = "Dark2") +
  colorspace::scale_colour_discrete_qualitative(palette = "Dark2") +
  labs(x = NULL, y = "Body mass (g)") +
  theme_minimal(base_size = 12) +
  theme(legend.position = "none",
        panel.grid.major.x = element_blank())

Three things to notice. First, the cloud, the box, and the points are three separate layers stacked in a specific order: clouds at the back, box in the middle, points on top. Second, justification = -0.2 shifts the cloud off the centre line so the box and points sit beside it rather than underneath. Third, the boxplot’s outlier points are hidden with outlier.shape = NA because all the raw data are already shown as jittered points; leaving them on would double-count.

Accessible colour with colorspace and colorBlindness

Two packages put the Block 1 principles into practice: colorspace builds the palette and colorBlindness checks it. Use them together, because a palette you have not checked leaves accessibility to chance.

fig <- penguins_complete |> 
  ggplot(aes(x = bill_length_mm, y = flipper_length_mm,
             colour = species, shape = species)) +
  geom_point(alpha = 0.8, size = 2) +
  colorspace::scale_colour_discrete_qualitative(palette = "Dark2") +
  labs(x = "Bill length (mm)", y = "Flipper length (mm)",
       colour = "Species", shape = "Species") +
  theme_minimal(base_size = 12)

# Inspect under simulated colour vision deficiency
colorBlindness::cvdPlot(fig)

The four-panel grid shows: the original, deuteranopia, protanopia, and a desaturated (greyscale) version. The figure passes if all groups remain distinguishable in all four panels. If any panel fails (typically deuteranopia or protanopia for red-green sensitive figures), strengthen the redundant encoding (shape or linetype), choose a more separated palette, or fall back to direct labelling.

This is the encoding hierarchy from Block 1 in practice: position handles the two continuous variables (rank 1), colour hue handles the categorical (rank 2 for categorical data), and shape is added as a redundant cue so that the figure does not depend on colour alone. Shape is a weaker encoding on its own, but as a backup it is what keeps the groups apart in the greyscale panel.

The figure with redundant shape encoding survives the desaturated panel because the shape carries the species information when the colour information collapses. The figure without redundant encoding becomes unreadable in greyscale.

Direct labelling with ggrepel and ggtext

A figure legend separates the colour key from the data: the reader’s eye has to travel from the data layer to the legend and back, holding a mapping in working memory. Direct labelling puts the group name on the data itself, so the eye reads the label as part of the data. For talks, posters, and public engagement, direct labelling is almost always clearer.

The problem is that labels placed at data points overlap each other. ggrepel::geom_text_repel() and ggrepel::geom_label_repel() solve this by moving labels iteratively until they no longer collide, with connector lines preserved. The example below uses geom_label_repel(), which draws each label on a small background box.

# Label location: one label per species at the species centroid
label_data <- penguins_complete |> 
  group_by(species) |> 
  summarise(x = median(bill_length_mm),
            y = median(flipper_length_mm),
            .groups = "drop")

penguins_complete |> 
  ggplot(aes(x = bill_length_mm, y = flipper_length_mm, colour = species)) +
  geom_point(alpha = 0.5, size = 1.5) +
  ggrepel::geom_label_repel(
    data = label_data,
    aes(x = x, y = y, label = species, colour = species),
    size = 5,
    fontface = "bold",
    label.size = 0,
    inherit.aes = FALSE
  ) +
  colorspace::scale_colour_discrete_qualitative(palette = "Dark2") +
  labs(x = "Bill length (mm)", y = "Flipper length (mm)") +
  theme_minimal(base_size = 12) +
  theme(legend.position = "none")

ggtext is the companion package for rich text: it allows markdown formatting inside titles, axis labels, and legend entries, and supports inline colour. This is what lets you write a title like "**Gentoo** penguins are <span style='color:#5F96C2;'>**substantially heavier**</span> than Adelie and Chinstrap" directly. To enable rich text on a theme element, set it to ggtext::element_markdown().

penguins_complete |> 
  ggplot(aes(x = species, y = body_mass_g, fill = species)) +
  ggdist::stat_halfeye(adjust = 0.5, justification = -0.2,
                       .width = 0, point_colour = NA, alpha = 0.8) +
  geom_boxplot(width = 0.12, outlier.shape = NA, alpha = 0.5,
               colour = "grey20") +
  colorspace::scale_fill_discrete_qualitative(palette = "Dark2") +
  labs(
    title = "<span style='color:#5F96C2;'>**Gentoo**</span> penguins are substantially heavier than <span style='color:#C87A8A;'>**Adelie**</span> and <span style='color:#6B9D59;'>**Chinstrap**</span>",
    x = NULL,
    y = "Body mass (g)"
  ) +
  theme_minimal(base_size = 12) +
  theme(legend.position = "none",
        plot.title = ggtext::element_markdown(size = 13, lineheight = 1.2))

Inline colour in the title removes the need for a separate legend entirely. The hex codes in the title are the three Dark2 colours used for the fills (colorspace::qualitative_hcl(3, palette = "Dark2") returns them), so the colours in the title match the fills in the data, and the reader makes the mapping in a single saccade.

These techniques put the direct labelling and highlighting rows of the audience table from Block 2 into practice. Reach for direct labels and inline-coloured titles when designing for posters, talks, or public engagement, where the reader cannot afford the eye-travel to a separate legend.

Multi-panel composition with patchwork

For panels showing the same chart type for different subsets of the data, use facet_wrap() or facet_grid(). For panels showing different chart types or different aspects of one analysis, use patchwork.

Three defaults apply for patchwork compositions: collect legends into a single shared legend, tag panels with uppercase letters, and use an explicit design = string for the layout. The string is self-documenting; you can rearrange the layout by editing the letters without rewriting the composition call.

pal <- colorspace::qualitative_hcl(3, palette = "Dark2")
names(pal) <- levels(penguins_complete$species)

p1 <- penguins_complete |> 
  ggplot(aes(x = species, y = body_mass_g, fill = species)) +
  ggdist::stat_halfeye(adjust = 0.5, justification = -0.2,
                       .width = 0, point_colour = NA, alpha = 0.8) +
  geom_boxplot(width = 0.12, outlier.shape = NA, alpha = 0.5) +
  scale_fill_manual(values = pal, name = "Species") +
  labs(x = NULL, y = "Body mass (g)") +
  theme_minimal(base_size = 11) +
  guides(fill = "none")

p2 <- penguins_complete |> 
  ggplot(aes(x = bill_length_mm, y = bill_depth_mm,
             fill = species, shape = species)) +
  geom_point(alpha = 0.7) +
  scale_fill_manual(values = pal, name = "Species") +
  scale_shape_manual(values = c(21,22,23), name = "Species") +
  labs(x = "Bill length (mm)", y = "Bill depth (mm)") +
  theme_minimal(base_size = 11)

p3 <- penguins_complete |> 
  count(species, island) |> 
  ggplot(aes(x = island, y = n, fill = species)) +
  geom_col(position = position_dodge2(preserve = "single")) +
  scale_fill_manual(values = pal, name = "Species") +
  labs(x = NULL, y = "Count") +
  theme_minimal(base_size = 11) +
  guides(fill = "none")

# Edit the letter grid below to rearrange panels.
# Letters refer to plots in the order they are added (A = p1, B = p2, C = p3).
layout <- "
AB
CC
"

p1 + p2 + p3 +
  patchwork::plot_layout(design = layout, guides = "collect") +
  patchwork::plot_annotation(tag_levels = "A") &
  theme(legend.position = "bottom",
        plot.tag = element_text(face = "bold", size = 12))
Noteguides

When you combine plots with patchwork and set guides = "collect", patchwork gathers legends from every panel and merges any it considers identical.

“Identical” is strict: the guides must share the same aesthetic, scale, breaks and title. If your panels encode the same grouping variable through different aesthetics (say fill in one panel and colour plus shape in another) or through different scales, patchwork treats them as distinct and shows one legend per panel rather than a single shared key.

  • First, decide which single legend should represent the shared variable across all panels, and choose the panel whose legend carries the most visual encoding, since that legend can serve as a complete key for the others.

  • Second, suppress the legends on the remaining panels with guides(<aesthetic> = "none").

Without step two you get this. The three panels below use different aesthetics and scales and none of them suppresses its legend, so patchwork collects three separate legends:

q1 <- penguins_complete |> 
  ggplot(aes(x = species, y = body_mass_g, fill = species)) +
  ggdist::stat_halfeye(adjust = 0.5, justification = -0.2,
                       .width = 0, point_colour = NA, alpha = 0.8) +
  geom_boxplot(width = 0.12, outlier.shape = NA, alpha = 0.5) +
  colorspace::scale_fill_discrete_qualitative(palette = "Dark2") +
  labs(x = NULL, y = "Body mass (g)") +
  theme_minimal(base_size = 11)

q2 <- penguins_complete |> 
  ggplot(aes(x = bill_length_mm, y = bill_depth_mm,
             colour = species, shape = species)) +
  geom_point(alpha = 0.7) +
  colorspace::scale_colour_discrete_qualitative(palette = "Dark2") +
  labs(x = "Bill length (mm)", y = "Bill depth (mm)") +
  theme_minimal(base_size = 11)

q3 <- penguins_complete |> 
  count(species, island) |> 
  ggplot(aes(x = species, y = n, fill = island)) +
  geom_col(position = "dodge") +
  colorspace::scale_fill_discrete_qualitative(palette = "Set 2") +
  labs(x = NULL, y = "Count") +
  theme_minimal(base_size = 11)

# Edit the letter grid below to rearrange panels.
# Letters refer to plots in the order they are added (A = q1, B = q2, C = q3).
layout <- "
AB
CC
"

q1 + q2 + q3 +
  patchwork::plot_layout(design = layout, guides = "collect") +
  patchwork::plot_annotation(tag_levels = "A") &
  theme(legend.position = "bottom",
        plot.tag = element_text(face = "bold", size = 12))

The & operator applies its right-hand side to every subplot already in the composition, so use it for global theme settings like legend position and tag formatting. The + operator applies only to the most recently added subplot.

Tip

Try later. Change the layout string so that panels A and C are stacked on the left and panel B occupies the full right column ("AB\nCB\n").

Use multi-panel composition for figures that combine several aspects of one analysis into a single figure. A typical journal “Figure 1” with three panels labelled A, B, C is almost always a patchwork composition, not a facet_wrap(). The layout string makes the composition easy to edit: if a reviewer asks you to rearrange the panels, you change the letters rather than rewrite the code.

Bonus: linked, interactive panels with ggiraph

Block 2 introduced ggiraph for a single plot. It also works on a whole patchwork composition, and that is where it gets fun: give every panel the same data_id, and hovering in one panel highlights the same group in all of them.

library(ggiraph)

i1 <- penguins_complete |>
  ggplot(aes(x = species, y = body_mass_g, colour = species,
             data_id = species,
             tooltip = paste0(species, ": ", body_mass_g, " g"))) +
  geom_jitter_interactive(width = 0.2, alpha = 0.6) +
  labs(x = NULL, y = "Body mass (g)")

i2 <- penguins_complete |>
  ggplot(aes(x = bill_length_mm, y = bill_depth_mm, colour = species,
             data_id = species,
             tooltip = paste0(species, ": ", bill_length_mm, " × ", bill_depth_mm, " mm"))) +
  geom_point_interactive(alpha = 0.7) +
  labs(x = "Bill length (mm)", y = "Bill depth (mm)")

i3 <- penguins_complete |>
  count(species, island) |>
  ggplot(aes(x = island, y = n, fill = species,
             data_id = species, tooltip = paste0(species, " on ", island, ": ", n))) +
  geom_col_interactive(position = position_dodge2(preserve = "single")) +
  labs(x = NULL, y = "Count")

linked <- (i1 + i2) / i3 &
  colorspace::scale_fill_discrete_qualitative(palette = "Dark2") &
  colorspace::scale_colour_discrete_qualitative(palette = "Dark2") &
  theme_minimal(base_size = 11) &
  theme(legend.position = "none")

girafe(ggobj = linked, width_svg = 8, height_svg = 6,
       options = list(opts_hover(css = "stroke:black;stroke-width:1.5px;"),
                      opts_hover_inv(css = "opacity:0.15;")))

Hover over any Gentoo point or bar and watch the other two panels follow. (Panel A is a strip of raw points rather than a boxplot: geom_boxplot_interactive() tags each box by its group number, not its species, so it would not link up.) The recipe is the same one you already know: interactive geoms, a shared data_id, then girafe(). Everything else (the patchwork layout, & for shared settings, the Dark2 palette) is unchanged from the static version.

Tip

Try later. Add opts_selection(type = "single") to the options list and click a group instead of hovering. Then save the figure for a lab website with htmlwidgets::saveWidget(girafe(ggobj = linked), "linked_penguins.html").
