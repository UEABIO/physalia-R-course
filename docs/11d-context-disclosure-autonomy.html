Block 4: Context, disclosure and autonomy

Two questions decide how far you can trust anything an AI assistant does with your code:

  1. What can it see? Its answers are only as good as its context, and everything it sees has left your machine.
  2. What can it do? An assistant that advises leaves you as the filter on every change. An agent that acts removes that filter.

This block covers both, using Claude Code in the terminal. If you use Posit Assistant instead, the collapsed boxes give the differences.

⏱ ~33 minutes

Part A: What can the assistant see?

Surface Example What it can see Can it act?
Browser chat Any chat website What you paste No
Terminal agent Claude Code Project files, and the output of any command it runs Yes, in your files and shell
Session-aware IDE assistant Posit Assistant in RStudio or Positron Your live R session (loaded packages, data frames, console history) and project files Yes, in your session and files
Note

Knowing versus guessing. An assistant can describe your data confidently for two quite different reasons: it has been given real information, or it is recalling patterns from training data. Only the first is reliable.

It has real information when you pasted the output, when it read a file, when the IDE injected your session, or when it ran code and read the result. It is guessing when none of those apply. The tells are a well-known dataset you never mentioned (mtcars, iris, penguins) or column names and values you never supplied.

Even with context, a model’s account of what it can see is unreliable. Check any data-specific claim against the real object.

Exercise 1: Context decides the answer

The same error, three levels of context (10 minutes)

1. Error only. In a browser chat, open a fresh session and paste only this, asking “What does this error mean?”:

Error in `mutate()`:
ℹ In argument: `mass_change = mass_post - mass_pre_g`.
Caused by error:
! object 'mass_post' not found

The answer can only reason from the error text.

2. Error plus code plus structure. In a new session, paste:

I am running this code:

  voles |>
    mutate(mass_change = mass_post - mass_pre_g)

and getting:

  Error in `mutate()`:
  ℹ In argument: `mass_change = mass_post - mass_pre_g`.
  Caused by error:
  ! object 'mass_post' not found

The data structure is:

  Rows: 72
  Columns: 6
  $ subject_id          <chr> "V001", "V002", "V003", ...
  $ sex                 <chr> "M", "F", "M", ...
  $ treatment_arm       <chr> "Control", "Control", ...
  $ mass_pre_g          <dbl> 28.3, 27.9, 30.1, ...
  $ mass_post_g         <dbl> 28.5, 28.0, 30.5, ...
  $ metabolic_rate_post <dbl> 13.21, 12.84, 13.55, ...

What is wrong?

It should name the missing _g suffix.

3. No paste at all. Save the failing code in a script in your project. Start Claude Code from the project folder and ask only: “Why does the mutate() call in my script fail?” Claude Code can open the script and run code to inspect the data.

Then ask: “How do you know the column names?” Compare its answer with what you know it was given. If it claims to have seen something it could not have seen, you have found the unreliability described in the callout above.

TipUsing Posit Assistant

Load the data in your R session and run the failing code, then ask Posit Assistant only: “Why did my last command fail?” A session-aware assistant can read your console history and the data frame without your pasting anything.

The lesson is not that one route is correct. The answer is only as good as the context, and context reaches the model by more than one route.

Disclosure: every route out of your machine

Everything an assistant sees is sent to a model provider. Data leave your machine by four routes:

  1. What you paste. Errors, outputs, printed results.
  2. Files it reads. A data file in the repository or project folder.
  3. Session context the IDE injects. Posit Assistant reads loaded packages, data frames and console history, so a data frame in memory can reach the model without any paste.
  4. Output of commands it runs. If an agent runs print(voles) or head data.csv, those values enter its context.

Before you decide what to show, know what the surface can already reach. A data file committed to the repository, or a tibble loaded in your session, may already be disclosed.

When you describe a data frame deliberately, three commands reveal increasing amounts:

  • names(voles) lists column names only, in their original order.
  • summary(voles) adds ranges, quartiles and missing-value counts for numeric columns: the shape of the data, not individual records.
  • glimpse(voles) or str(voles) adds the first few actual values of every column.
Important

Before using an assistant on research data, check three things: whether your institution permits sending this kind of data to this provider; whether your ethics approval and data-sharing agreements allow it; and whether a synthetic or anonymised copy would serve instead. Tool settings that restrict reading (see the enforced-controls block) reduce accidental exposure, but they do not make an agent safe for confidential data: any command it runs that prints data sends that data to the provider.

For personal or confidential data, let the agent work on a synthetic copy and run the final code on the real data yourself, outside the agent’s workspace. Hooks and project settings are also code that runs on your machine, and a cloned repository can carry its own; trust only repositories whose configuration you have read.

Context you hold in your head

Instructor demonstration, about 3 minutes.

A data file can supply column names and types, but not your scientific question or your design intent. Your instructor will ask a fresh chat this:

I have a dataset with pre and post measurements. How should I analyse it?

and then, in a new session, this:

I have 72 voles, balanced across three treatment arms (Control, Low_dose,
High_dose) and two sexes (M, F). Each animal has body mass measured before
and after treatment, and a single post-treatment metabolic-rate reading.

My question is whether the high-dose treatment changes mass relative to
control, and whether the effect differs between sexes.

The dataset is small (n = 12 per cell). I will report effect sizes alongside
any inferential test. Given this design, what is a defensible primary
analysis, and what are the main threats to its validity?

The first returns a tour of options (paired tests, change scores, ANCOVA, mixed models); the second can return a recommendation, because the design and the question now exist outside your head. Treat even the better answer as a proposal to check against a statistics text or a colleague. Choosing the primary analysis is your decision, not the assistant’s.

Part B: What can the assistant do?

The model is the same at every level below. What changes is what it is permitted to do, and therefore where you sit in the loop.

Rung What happens Claude Code Posit Assistant
0. Suggest Completes the line you are typing — Next Edit Suggestions
1. Ask Answers; changes nothing Ask a question in plan mode Ask mode
2. Plan Proposes steps; changes nothing until you approve plan mode /plan
3. Act, with approval Edits files and runs commands, asking first default mode Normal mode
4. Act, partly unsupervised Some actions without asking acceptEdits mode Auto mode
5. Act, unsupervised No prompts bypassPermissions YOLO mode

A sixth rung, acting remotely on a branch and returning a pull request, is covered in Going further below.

In Claude Code, Shift+Tab cycles default, acceptEdits and plan. In Posit Assistant, /plan, /auto, /yolo and /restricted switch modes. Use rungs 0 to 3 throughout this course. Do not use rung 5.

Warning

Read the rung’s small print. acceptEdits in Claude Code approves more than edits: it also auto-approves common file commands such as mkdir, touch, mv and cp. A cp that overwrites a raw data file needs no approval in that mode. Posit Assistant’s auto mode replaces your judgement with a classifier model’s. Each step up the ladder removes a moment when you would have seen the action before it happened.

Approval fatigue is real. At rung 3, an approval prompt you click through without reading is rung 5 with extra steps. The enforced-controls block covers the rules that hold however tired you are.

Higher rungs make standing instructions matter more. In Ask mode, a convention the assistant does not know costs you a re-read. In agent mode, the assistant acts on its guess, and the guess lands in your files. That is why the instructions-and-skills block comes next, and why the enforced-controls block follows it.

Exercise 2: The same task, rising autonomy

Ask, plan, act (15 minutes)

Use your forked workshop repository, committed and clean, so every change is a diff you can inspect or revert. Never run an agent with uncommitted work you are not prepared to lose.

1. Ask. Start Claude Code in plan mode (claude --permission-mode plan) and ask:

In scripts/clean_voles.R, how would I add a column mass_change equal to
mass_post_g minus mass_pre_g?

Read the answer. Confirm with git status that nothing changed.

2. Plan. Still in plan mode, give a goal that spans several files:

In the voles pipeline, add a derived mass_change column (mass_post_g minus
mass_pre_g) in the cleaning step, create a new script that plots mass_change
by treatment_arm, and make sure the pipeline still runs end to end.

Before approving, check that the plan names every file it will touch, does not touch raw data, says where the plot script goes, and says how it will check the pipeline runs. Amend the plan in conversation if any of that is missing.

3. Act, with approval. Approve the plan and make sure you are in default mode, in which Claude Code asks before each edit or command (Shift+Tab switches modes). Read each approval prompt before answering it. Refuse at least one action you consider out of scope, and note how the agent responds.

4. Review. When it finishes:

git status
git diff

Read the diff as you would a colleague’s contribution. The agent’s statement that the pipeline “still runs” is a claim; run the pipeline yourself to check it.

5. Compare. At which rung did you decide the most? At which rung would you have missed an unwanted change if you had not read the diff?

6. Start your AI-use log. Create docs/ai-log.md and write the first line yourself, rather than asking the agent, in the form set out in Block 1:

2026-10-19; Claude Code (model as reported in the session); added mass_change
and a plot script; kept both after reading the diff; rejected one
out-of-scope edit.

Commit it with the agent’s changes. You will add a line after each block in which an agent does work.

TipUsing Posit Assistant

Use Ask mode for step 1, /plan for step 2, and Normal mode for step 3. The review in step 4 is the same: git status and git diff in the terminal.

Note

Access and cost. Plans and prices change; check before the session.

  • Claude Code needs an Anthropic account, used through a subscription or an API key; see Anthropic’s documentation for current options.
  • Posit Assistant uses Posit AI Pass or your own provider key, including an Anthropic API key. In RStudio, providers are configured in the assistant’s settings.
  • GitHub Copilot bills in AI credits; check GitHub’s plans page for what your plan includes.
  • Your institution may have approved some of these tools and not others.
NoteCheck · Reproduce · Record
  • Check: git status and git diff after every agent action; the agent’s report that something “still runs” is a claim until you run it.
  • Reproduce: work only in a committed, clean repository, so every change is a diff you can inspect or revert.
  • Record: your AI-use log starts here, in docs/ai-log.md.

GitHub Copilot and the remote rung

GitHub Copilot offers the same ladder in its own surfaces. Copilot Chat on github.com can also see files in the repository you open it from.

Rung GitHub Copilot
0. Suggest Inline suggestions
1. Ask Ask in Chat
2. Plan Plan mode in the IDE
3. Act, with approval Agent mode, approving each tool call
4. Act, partly unsupervised Agent mode with auto-approval
5. Act, unsupervised —
6. Act remotely Cloud agent

The sixth rung, the Copilot cloud agent, works on the repository on GitHub, in an environment GitHub runs. It takes a task such as an issue, works on its own branch and returns a pull request. Copilot Free includes only limited agent features; check GitHub’s plans page to see whether your plan includes the cloud agent. The cloud agent appears in the Going further section of the characterisation-test block, where its pull request meets a review gate.
