Block 5: Instructions and skills

The higher an agent works on the autonomy ladder, the more its guesses about your conventions land in your files. This block shows you how to state those conventions once, so every conversation follows them, in two ways:

  • An instruction fileA file the assistant loads into every conversation, such as AGENTS.md or CLAUDE.md, stating the project’s standing conventions. Its contents are requests, not guarantees. loads into every conversation. Use it for what is always true: structure, style, reproducibility rules.
  • A skillA folder containing a SKILL.md file (and optionally scripts and templates) that an assistant loads only when it is invoked by name or judged relevant from its description. loads only when needed: a procedure such as producing a publication figure or cleaning data against a codebook.

Both are requests the model usually follows; Block 6 covers rules that hold every time.

⏱ ~45 minutes

Part A: Instructions

Your conventions live in one file, AGENTS.md, at the repository root, and both Claude Code and Posit Assistant read it at the start of every conversation. There is no CLAUDE.md: Claude Code reads AGENTS.md only when no CLAUDE.md exists, so creating one (for example with /init) would hide your conventions.

Instructions that work are:

  • one per line, and specific enough to check (“use the native pipe |>”, not “write clean code”);
  • true of your own code, or the model gets mixed signals;
  • short, because the file loads into every request;
  • added when a mistake repeats: a correction in chat is forgotten next conversation;
  • not guarantees: “never edit raw data” belongs here and in the enforced controls of Block 6.

Activity: Make AGENTS.md yours

Your workshop repository already contains a starter AGENTS.md. Make it describe your practice, then prove that Claude Code reads it.

NoteThe starter AGENTS.md

It includes a canaryA fixed line that an instruction file asks the assistant to include in its output, so that seeing the line shows the file was loaded. It does not show that the other rules were followed.: a fixed first line the assistant is asked to put in any R code it writes, so you can see the file was loaded. The “Tests” rules ask the agent to prove its own work after every edit, which later blocks rely on.

# Project conventions: voles analysis

## Canary
When you write or edit R code, make the first line of the first code block:
# agents-md: active v1

## Structure
- Raw data live in data/raw/ and are never modified.
- Derived data go to data/derived/; figures and tables go to outputs/.
- Reusable functions live in scripts/functions/.

## R style
- Tidyverse style, native pipe |>, snake_case names, <- for assignment.
- Write TRUE and FALSE, never T and F.
- Build every path with here::here() (or here() after library(here)). Never
  use setwd() or rm(list = ls()).
- Read CSV files with readr and explicit col_types.

## Reproducibility
- Packages are managed with renv. Do not call install.packages(); ask before
  adding a package.
- Do not edit renv.lock.
- Set a seed immediately before any random step.
- Every script must run in a fresh R session.
- Every script must run with Rscript from the project root; after writing one,
  run it that way and report the exit status.
- Save figures with ggsave() to outputs/.

## Tests
- After editing any R file, run Rscript -e "testthat::test_dir('tests')" and
  paste the final summary line verbatim.
- Never edit anything in tests/fixtures/, an existing expectation or a
  tolerance to make a test pass.
- Every new function in scripts/functions/ gets a test with at least one
  known-answer case on a small tibble, including an NA; expected values are
  worked out by hand, never by running the code under test.

## Data integrity
- Never drop rows silently; state the reason for every filter in a comment.
- Report the number of observations behind every summary statistic.

## Statistics
- Label each analysis as exploratory or confirmatory.
- Never type numerical results into text; compute them in code.

## Working with me
- Before changing more than one file, present a plan and wait for approval.
- Do not edit anything under data/raw/, tests/fixtures/ or .github/.

Edit, check, verify (15 minutes)

Start state: your workshop repository open, a clean Git pane, and Claude Code running in the project’s Terminal tab (checking work).

1. Baseline.

Prompt (Claude Code):

/plan Read data/raw/voles_metabolism.csv and make a quick exploratory plot
of mass_post_g by treatment arm. Show the R code in your reply; do not
create any files.

Look for the canary, # agents-md: active v1, as the first line of the code. (Asking for the code in the reply gives the canary somewhere to appear.)

2. Make it yours. Type /memory, choose AGENTS.md, and in your editor:

  1. delete one rule you do not actually follow;
  2. add one convention you always follow.

Keep the canary and the “Tests”, “Statistics” and “Working with me” sections, which later blocks rely on. Save.

3. Verify. Type /clear and repeat the step 1 prompt. The canary shows the file was loaded; check the plot code against your new rule to see whether it was followed.

4. Check it with a test. In the R console, after Session → Restart R:

testthat::test_file(here::here("tests", "test_controls.R"))

It confirms AGENTS.md is in place with its canary, the project still starts in Manual mode, and the deny rules are intact. Commit AGENTS.md from the Git pane.

You are done when the canary appears, the test passes, and your edited AGENTS.md is committed.

If it goes wrong: check there is no CLAUDE.md (the test checks this too) and that /memory lists AGENTS.md. Still stuck? Compare with the block5-done branch from the Git pane’s branch menu.

TipUsing Posit Assistant

Posit Assistant reads the same AGENTS.md. Open it from the gear menu (Open project memory), or describe your conventions and run /savememory. If the canary is missing, check that you trusted the workspace.

Part B: Skills

A skill is a folder holding a SKILL.md file, plus any scripts or templates it needs. Its front matterThe block between two lines of three dashes at the top of a file, holding settings such as a skill’s name and description, or a Quarto document’s options., between two lines of three dashes at the top, gives a name and a description:

  • The description is the trigger. “Use when producing a ggplot2 figure for a report, poster or paper” loads when it should; “for plots” loads erratically. Invoking it by name (/skill-name) always works.
  • The body is a procedure: when to use it, the steps, hard rules and a final check. It loads only when used, so it can be longer than AGENTS.md.
TipBackground: skills that run only by name

For a skill that writes files, disable-model-invocation: true in the front matter makes it run only when you invoke it by name.

Keep the master copy in .agents/skills/ and copy it into .claude/skills/ for Claude Code (Posit Assistant reads .agents/skills/ directly). The deny rules protect .claude/ from the agent’s edit tools but not .agents/skills/, so check the master copy in the Git pane too. The course’s own skills already ship in both; type /skills to list them. For a skill you write, copy it once, and again whenever you change it:

In the R console:

fs::dir_copy(
  here::here(".agents", "skills", "house-figures"),
  here::here(".claude", "skills", "house-figures"),
  overwrite = TRUE
)

Activity: Write a skill and test it

A house figure style (20 minutes)

Start state: Claude Code in Manual mode in your project’s Terminal tab, with your AGENTS.md committed.

1. Baseline, before the skill exists.

Prompt (Claude Code):

Make a figure of mass_post_g by treatment_arm for the voles data, for a
lab report. Save the code as scripts/fig_baseline.R.

Approve the edit. Doing this first guarantees the baseline was written without the skill.

2. Create the skill. In the R console, usethis::edit_file(".agents/skills/house-figures/SKILL.md") creates and opens the file. Paste in:

---
name: house-figures
description: >-
  Applies this project's conventions to any ggplot2 figure that will appear
  in a report, poster or paper. Use when asked to create, revise or polish a
  figure for presentation. Not for quick exploratory plots.
---

# House figure style

## Rules
1. Where any group has fewer than 30 observations, show every observation
   (jittered points or a dot plot) with a summary overlaid. Never draw a bar
   with error bars ("dynamite plot").
2. Colour categorical groups with the Okabe-Ito palette
   (grDevices::palette.colors(palette = "Okabe-Ito")), and map the same
   variable to point shape so the figure works without colour.
3. Axis titles give the quantity and its unit, for example "Body mass (g)".
4. Use theme_classic(base_size = 12).
5. Show the number of observations per group on the figure.
6. Never add p-values or significance markers unless the user supplies a
   fitted model and asks for them.

## Before returning code
List which rules you applied, and any you could not apply and why.

Copy it into .claude/skills/ with the fs::dir_copy() line above (you do this yourself, because .claude/ is protected from the agent). Type /skills: house-figures should be listed, with no restart.

3. With the skill.

Prompt (Claude Code):

/house-figures Make a figure of mass_post_g by treatment_arm for the voles
data, for a lab report. Save the code as scripts/fig_house.R.

4. Grade it. Run both scripts in a fresh R session and look at the figures: callr::rscript(here::here("scripts", "fig_baseline.R")), then the same for fig_house.R. Then record, for each rule:

Rule Without skill With skill
1. Raw data shown; no dynamite plot
2. Okabe-Ito colour plus shape
3. Units in axis titles
4. theme_classic(base_size = 12)
5. n per group shown
6. No unrequested p-values

5. Record it. Add a line to docs/ai-log.md in the same form as Block 4, with today’s date, naming the skill you tested and what you kept or changed in its output. Commit it with the skill and the two scripts.

You are done when the table is filled in from the figures you looked at, not from the agent’s list of rules it applied, and your log line is committed.

If it goes wrong: if /skills does not list it, check that .claude/skills/house-figures/SKILL.md exists and its front matter starts and ends with three dashes. Out of time? Commit or discard your changes in the Git pane first, so the switch is not blocked, then switch to block5-done.

Payoff. What did the skill do for you, how long did checking it take, and would you use it for the next figure?

TipStretch: test the trigger

In a new conversation (/clear), test the trigger: “Give me a quick look at mass_post_g by arm” should not load the skill; “Polish the figure in scripts/fig_baseline.R for the poster” should. Or test rule 6: ask it to “add significance stars between the groups in scripts/fig_house.R” and see whether it declines. Either way, what makes the output trustworthy is the grading in step 4, which you can repeat on every figure.

TipUsing Posit Assistant

Posit Assistant reads .agents/skills/ directly, so no copy is needed. Invoke the skill by name in the same way.

TipA rule for Quarto files only

Some rules are right for one kind of file and wrong elsewhere. A chunk option such as #| echo: false is meaningful in a .qmd file and meaningless in an .R script. The test for a scoped rule: would it be wrong, not merely irrelevant, in the files it excludes? If not, put it in AGENTS.md.

Create and test a scoped rule

The rules themselves:

# Quarto document conventions

- Set chunk options with the hashpipe (#|) inside the chunk, not in the
  {r} header.
- Give every chunk a label; prefix figure chunks with fig-.
- Every figure chunk sets #| fig-cap:, #| fig-width: and #| fig-height:.
- Refer to figures in the text with @fig-..., never by a typed number.
- Default to #| echo: false unless the document is a code walkthrough.
- Resolve paths with here::here(); never assume the working directory is the
  document's folder.

(The “hashpipe” is the #| at the start of a chunk-option line.) Place them where your tool looks:

  • Claude Code: .claude/rules/quarto.md, beginning with front matter that restricts it to Quarto files:

    ---
paths:
  - "**/*.qmd"
---

  • Copilot: .github/instructions/quarto.instructions.md, beginning with this front matter:

    ---
applyTo: "**/*.qmd"
---

  • Posit Assistant: no path-scoped instruction file is documented. Add the rules to AGENTS.md under a heading such as “When editing .qmd files”, or rely on its built-in quarto-authoring skill.

Test. Open a .qmd file and ask for a chunk that plots mass_post_g by treatment_arm. A correct answer uses hashpipe options, a fig- label, a caption and here::here(). Then ask for the same plot in an .R script; the Quarto rules should not appear. If they do not appear in the .qmd either, the rule is not loading on your surface. Report what you found; behaviour differs between tools.

Every scoped rule is a second copy of a convention to keep in step, once per tool. Use scoped rules sparingly.

# Publication figures

This skill governs production of figures that will be seen by an external audience. It is self-contained: the house rules below apply even if the project has no instruction file.

## House rules

- Tidyverse style, native pipe `|>`, `here::here()` for every path.
- British spelling in titles, labels, legends and comments.
- Never produce pie charts, dual y-axes, 3D effects, or bar charts with error bars ("dynamite plots") when the raw data exist.

## Missing information

If information you need is missing (the audience, a variable's unit, the fitted model), ask the user once, in a single message, before writing code. If the user tells you to proceed without it, or you are working unattended (for example as a cloud agent on a pull request), choose the safe default this skill gives, record the choice in a code comment and, if there is one, in the pull request description, and continue.

## Project toolkit

The packages this skill uses are listed below. Check that each one you need is
in `renv.lock`; if one is missing, stop and ask before installing anything:

- `ggplot2`, `patchwork`, `here`, `scales` for core plotting, composition, paths, and label formatting.
- `ggdist` for raincloud and half-eye distributions: `stat_halfeye()`, `stat_pointinterval()`.
- `ggbeeswarm` for moderate-n group displays: `geom_quasirandom()`.
- `colorspace` for palettes: `scale_*_discrete_qualitative(palette = "Dark 2")`, `scale_*_continuous_sequential(palette = "Viridis")`, `scale_*_continuous_diverging(palette = "Blue-Red")`, and the HCL generators (`sequential_hcl()`, `diverging_hcl()`) used by the brand-seeded scales in `theme-project.R`.
- `emmeans` for estimated marginal means and pairwise contrasts: `emmeans(model, specs = "var")`, `pairs(emm, adjust = "tukey")`.
- `ggpubr::stat_pvalue_manual()` as the rendering layer for emmeans-derived contrasts. Never `ggpubr::stat_compare_means()`, which performs unadjusted pairwise t-tests by default.
- `ggh4x` for nested or hierarchical faceting: `facet_nested()`, `facet_nested_wrap()`, `guide_axis_nested()`.
- `ragg` for raster output via `ggsave(device = ragg::agg_png)`.
- `colorBlindness::cvdPlot()` for the colour-vision-deficiency check.
- `showtext` (optional) for the project font; without it `theme_project()` falls back to the device's default font.

Do not introduce additional plotting packages without amending this list. Do not reach for `cowplot` themes when `theme_minimal()` or `theme_project()` will do. Do not hand-write manual hex colour vectors as data scales: use the `colorspace` palettes or the brand-seeded constructors in `theme-project.R`, both of which keep palettes CVD-checkable. A single fixed colour for a single-group or highlight geom is permitted and is not a "data scale".

## Using the files in this skill

Source the theme and palette functions from the skill folder:

```r
source(here::here(".agents", "skills", "pub-figures", "theme-project.R"))
```

If the folder was copied into `.claude/skills/` rather than linked, use that path instead. `theme_project()` here is the full version of the simple `theme_project()` from the ggplot chapter: same name and `base_size` argument, plus a font, furniture colours and an `axis_type` argument.

## Audience must be determined first

Identify the audience as one of `journal-lab-report`, `poster`, `talk`, or `public-engagement` before writing any plotting code. Styling, annotation density, and title framing all depend on the answer.

If the audience is not specified, ask (see *Missing information*). If proceeding without an answer, default to `journal-lab-report` and record the assumption at the top of the script:

```r
# Audience not specified; defaulting to journal-lab-report.
# Re-run with explicit audience if poster, talk, or public-engagement intended.
```

Then state in one sentence each: the variables and their types (continuous, discrete, date/time), the scientific question, the chart type the variable structure calls for, whether raw data will be shown, and whether statistical annotations are required.

## Statistical annotations require a model object

Do not annotate test statistics, p-values, or confidence intervals unless a fitted model object exists: fitted by code in this project that you have run or can read, or present in the user's live R session where your tool can see it. Fabricating values from descriptive data is a serious error. If there is no model, omit annotations and insert this placeholder for the legend:

> LEGEND PLACEHOLDER. Model object required to supply the test statistic, degrees of freedom, p-value, and adjustment method. Do not fabricate.

## Chart selection

| Variable 1 | Variable 2 | Variable 3 | Default chart |
|------------|------------|------------|---------------|
| Continuous | — | — | Raincloud (`ggdist::stat_halfeye` + boxplot + jitter) |
| Continuous | Continuous | — | Scatter plot |
| Continuous | Continuous | Discrete | Scatter, colour and shape mapped to discrete |
| Discrete | — | — | Bar chart of counts |
| Discrete | Continuous | — | Raincloud per group; boxplot if many groups; bar only if one summary value per group |
| Discrete | Discrete | — | Heatmap of counts |
| Discrete | Discrete | Continuous | Heatmap of the continuous variable |
| Date | Continuous | — | Line chart |
| Date | Continuous | Discrete | Line chart, one line per group |

If a chart not in this table is requested, select the closest matching entry, generate the code, and record both the request and the substitution in a comment at the top of the script (and in the pull request description, if there is one).

## Colour

The colour-vision-deficiency check (`cvdPlot()`, below) is the final arbiter: a palette that fails it must be replaced, regardless of brand intent.

**No brand specified (default).** Use `colorspace::scale_*` functions, matched to data structure.

**Brand specified.** When the request names a brand colour (for example, "use a brand colour of darkblue"), call `set_brand("darkblue")` once after sourcing `theme-project.R`. `set_brand()` accepts any R colour name or hex string. The brand colour then seeds:

- single-colour and highlight geoms, via `brand_base()`;
- sequential continuous scales: `scale_*_brand_seq()`;
- the **high** arm of diverging continuous scales: `scale_*_brand_div(midpoint = <value>)`. The low arm is the brand's complementary hue, so the two arms always contrast, unless you name a second brand colour with `set_brand(<brand>, div_low = <colour>)`.

**Categorical colour is never brand-seeded.** One seed colour cannot generate a coherent, CVD-safe set of distinct hues. For unordered groups, use `colorspace` "Dark 2"; `scale_*_brand_qual()` in `theme-project.R` is the same palette and takes no `base` or `n` argument. The brand colour can still mark one focal group, with the other groups in grey.

| Data structure | Palette type | colorspace default | With a brand set |
|----------------|--------------|--------------------|------------------|
| Discrete, unordered groups | Qualitative | `Dark 2` | `Dark 2` (`scale_*_brand_qual()` is identical) |
| Discrete, ordered groups | Sequential discrete | `Purples 3` | `Purples 3` (the brand scales are continuous only) |
| Continuous, one-directional | Sequential | `Viridis` | `scale_*_brand_seq()` |
| Continuous, midpoint-centred | Diverging | `Blue-Red` | `scale_*_brand_div()` |

If a brand-seeded scale fails the CVD check, replace it with the colorspace default in the same row and record the fallback in a comment.

Categorical groupings must use redundant encoding: shape for points, linetype for lines. Colour alone is not sufficient.

## Audience-specific styling

| Element | Journal / lab report | Poster | Talk | Public engagement |
|---------|---------------------|--------|------|-------------------|
| Title above figure | No | Yes (explanatory) | Yes (explanatory) | Yes (explanatory) |
| Figure legend below | Yes (four elements) | Optional, abbreviated | No | No |
| Direct labelling | Sparingly | Yes | Yes | Yes |
| Highlighting (grey out non-focal) | No | Yes | Yes | Yes |
| Reference lines | Sparingly | Yes | Yes | Yes |
| Statistical annotations | Precise p-values | Abbreviated | One key result | None |
| Base font size | 12 pt floor | 16 to 20 pt | 14 to 18 pt | 14 to 18 pt |
| Raw data shown | Always where n permits | Always | Always | Where it clarifies |

`theme_project()` defaults to `base_size = 12`, the journal/lab-report floor. Raise it explicitly via `theme_project(base_size = ...)` for poster, talk, and public-engagement figures per this table.

Descriptive titles state what the figure shows. Explanatory titles state what it means. Journal figures put descriptive framing in the legend, not the title.

## Showing raw data

| n per group | Display |
|-------------|---------|
| Up to ~30 | Strip plot or raincloud, all points visible |
| ~30 to ~300 | Raincloud with jittered points, alpha 0.3 to 0.5 |
| ~300 to ~3000 | Beeswarm or 2D density |
| > ~3000 | Hexbin or 2D contour |

## Statistical annotations workflow

Pairwise contrasts come from `emmeans::emmeans()` and `emmeans::pairs()` with an explicit adjustment method (`tukey`, `holm`, or similar). Render brackets with `ggpubr::stat_pvalue_manual()`, supplying a data frame of contrasts.

Filter to significant contrasts before drawing. Format p-values with `scales::label_pvalue()` so very small values appear as `<0.001` rather than `0.000`.

A worked example is in `emmeans-bridge.R`.

## Error bars

Three options, not interchangeable:

- **Standard deviation:** spread of individual observations. Use when describing population variability.
- **Standard error of the mean:** precision of the sample mean. Shrinks with sample size.
- **95% confidence interval:** the recommended default. Prefer model-based intervals via `emmeans` where a model exists, otherwise from `stat_summary(fun.data = mean_cl_normal)`.

The choice must appear in the y axis label.

## Multiple panels and shared legends

When composing panels with `patchwork` and `plot_layout(guides = "collect")`, collection merges only guides that are identical in aesthetic, scale, breaks, and title (`name`). It deduplicates by guide specification, not by visual appearance, and it never removes a guide it judges different. Two failures follow: panels that encode the same variable through different aesthetics (`fill` in one, `colour` plus `shape` in another) or different palettes produce one legend each; and a panel encoding a genuinely different variable produces its own legend, which is correct.

Resolve the layout from the plot specifications:

- **Same variable, same palette, across all panels:** produce one shared legend. Designate the panel with the richest encoding (e.g. colour plus shape) as the legend-bearer, because that legend is a complete key for the simpler panels but not the reverse. Apply the identical scale call and an identical `name` in every panel, then suppress the guide on every non-bearing panel with `guides(<aesthetic> = "none")`. Record the choice of bearer in a comment.
- **Panels encode different variables:** do not force collection into one key. Keep the separate legends; merging them would mislabel a panel.

A mismatched `name`, a differing aesthetic or scale, or a missing suppression line will silently leave more than one legend for the same variable. After composing, confirm exactly one legend appears per distinct variable. A worked skeleton is in `patchwork-template.R`.

## Saving

Always save to `outputs/figures/` via `here::here()` in both PDF and PNG formats. Specify `width`, `height`, `units`, and `dpi` explicitly; do not rely on `ggsave()` defaults. Use `ragg::agg_png` as the device for PNG output with `bg = "white"`. PDF uses the default device.

If the four-panel simulation shows groups becoming indistinguishable under deuteranopia, protanopia, or tritanopia, the palette or redundant encoding must be revised. ## Pre-flight checklist (agent-verifiable items only)

Before declaring the script complete, confirm:

- Both axes labelled with name and unit, or just name for dimensionless variables.
- Bar chart axes start at zero; other axes cropped to the data range.
- Faceted panels share scale unless a comment justifies freeing it.
- Composite figures collect to one legend per distinct variable; non-bearing panels suppress their guide with `guides(... = "none")` and all retained scales share an identical `name`.
- Palette applied via `colorspace::scale_*` functions or the brand-seeded constructors in `theme-project.R`, never hand-written hex vectors as data scales. Single fixed colours for single-group or highlight geoms are permitted.
- Categorical colour uses `Dark 2` (directly or via `scale_*_brand_qual()`), not a brand-seeded palette.
- A brand-seeded scale that the colour-vision-deficiency check would fail is replaced by its `colorspace` default; the fallback is recorded in a comment.
- Categorical grouping carries redundant encoding (shape or linetype).
- Statistical annotations sourced from a fitted model object, never from descriptive data.
- None of the forbidden chart types in *House rules*.
- Default theme is `theme_project()`, `theme_minimal()`, or `theme_classic()`. Never `theme_grey()`.
- `theme_project()` base font size matches the audience floor (12 pt journal; 14 to 20 pt otherwise).
- File saved to `outputs/figures/` as both PDF and PNG with explicit dimensions.
- `cvdPlot()` call, wrapped in `if (interactive())`, inserted at the end of the script with a comment flagging it for the investigator.

# Project theme and palette construction for ggplot2.
#
# Colour policy (authoritative; see pub-figures SKILL.md):
#   * No brand set         -> use colorspace palettes directly.
#   * Brand set            -> set_brand("darkblue") sets the base colour (used by
#                             single-colour and highlight geoms) and reseeds the
#                             sequential ramp and the diverging HIGH arm. The
#                             low arm becomes the brand's complementary hue
#                             unless set_brand() is given div_low. Sequential
#                             and diverging are
#                             generated via colorspace HCL generators
#                             (CVD-robust, monotonic luminance).
#   * Categorical colour is NEVER brand-seeded: scale_*_brand_qual() delegate to
#                             colorspace "Dark 2", which sizes itself to the data.
#                             A single seed cannot make a coherent multi-hue set.
#   * Single-group / highlight geoms default to brand_base(), teal until reset.
#
# Manual hex palettes are NOT used as data scales. Only the base colour is used
# directly, and only for single-colour or highlight geoms.
#
# theme_project() here is the full version of the simple theme_project() taught
# in the ggplot chapter (Block 3: Themes and scales). It keeps the same name and
# base_size argument, and adds a font, furniture colours and axis_type.
#
# Dependencies: ggplot2 (>= 3.5), colorspace, scales; showtext + sysfonts for
#   fonts (optional: without them the device's default font is used);
#   colorBlindness for the accessibility check.
# ==============================================================================

library(ggplot2)
library(colorspace)

# ---- Brand state and setter --------------------------------------------------
# A single mutable brand state lets one call rebrand everything downstream.
# `set_brand("darkblue")` sets the base colour, which seeds the sequential ramp
# and the diverging high arm. Accepts any R colour name or hex string.

.brand_state <- new.env(parent = emptyenv())
.brand_state$base    <- "#09baba"  # teal default
.brand_state$div_low <- "#2c4977"  # navy default for the diverging low arm

#' Normalise a colour name or hex to a hex string
#' @keywords internal
.as_hex <- function(col) {
  rgb <- grDevices::col2rgb(col)  # accepts R colour names and hex
  grDevices::rgb(rgb[1], rgb[2], rgb[3], maxColorValue = 255)
}

#' Set the project brand colour
#'
#' Sets the base colour used by single-colour and highlight geoms, the
#' sequential ramp and the diverging high arm. Call once at the top of a
#' script: `set_brand("darkblue")`. Accepts any R colour name or hex string.
#'
#' @param base Brand colour (name or hex).
#' @param div_low Optional colour for the diverging low arm. If `NULL` (the
#'   default), the low arm uses the hue opposite the brand colour on the HCL
#'   colour wheel, so the two arms always contrast.
#' @return Invisibly, the resolved brand state as a list.
#' @export
set_brand <- function(base, div_low = NULL) {
  .brand_state$base <- .as_hex(base)
  .brand_state$div_low <- if (is.null(div_low)) {
    .complement_of(.brand_state$base)
  } else {
    .as_hex(div_low)
  }
  invisible(as.list(.brand_state))
}

#' Colour with the opposite HCL hue, for the diverging low arm
#' @keywords internal
.complement_of <- function(col) {
  hue <- (.hue_of(col) + 180) %% 360
  colorspace::hex(colorspace::polarLUV(L = 40, C = 60, H = hue), fixup = TRUE)
}

#' Reset the brand to the teal/navy default
#' @return Invisibly, the resolved brand state as a list.
#' @export
reset_brand <- function() {
  .brand_state$base    <- "#09baba"
  .brand_state$div_low <- "#2c4977"
  invisible(as.list(.brand_state))
}

#' Current brand base colour
#'
#' Returns the current brand base as a hex string. It is a function, not a value,
#' so it reflects the most recent `set_brand()` call. Use as `brand_base()`.
#' @return A hex colour string.
#' @export
brand_base <- function() .brand_state$base

# ---- Internal: font registration ---------------------------------------------

# Returns TRUE if `family` is available to showtext, FALSE otherwise, so the
# theme can fall back to the device's default font rather than warn on every
# text element.
.register_project_font <- function(family = "Open Sans") {
  if (!requireNamespace("showtext", quietly = TRUE)) {
    return(FALSE)
  }
  showtext::showtext_auto(enable = TRUE)
  if (!(family %in% sysfonts::font_families())) {
    try(sysfonts::font_add_google(family, family), silent = TRUE)
  }
  family %in% sysfonts::font_families()
}

# ---- theme_project() ---------------------------------------------------------

#' Project theme
#'
#' A composable ggplot2 theme controlling non-data aesthetics only. It sets no
#' data-encoding colours; pair it with a scale constructor (see below). Furniture
#' colours (title, axis labels, gridlines) are decorative and need not be
#' CVD-safe; the strip background is deliberately neutral grey so it is not
#' mistaken for a data signal when a fill palette is present. Furniture colours do
#' not track the brand by design; rebrand them by editing the literals below.
#'
#' @param base_size Base font size in points. Default 12 (journal/lab-report
#'   floor; raise to 14-20 for poster, talk, or public-engagement).
#' @param base_family Base font family. Default "Open Sans".
#' @param base_line_size Base line size. Default 0.5.
#' @param base_rect_size Base rectangle size. Default 0.5.
#' @param axis_type "categorical" or "continuous"; controls gridlines.
#' @return A ggplot2 theme object.
#' @export
theme_project <- function(base_size = 12,
                          base_family = "Open Sans",
                          base_line_size = 0.5,
                          base_rect_size = 0.5,
                          axis_type = c("categorical", "continuous")) {

  axis_type <- match.arg(axis_type)
  if (!.register_project_font(base_family)) {
    base_family <- ""  # device default font
  }

  title_col <- "#2c4977"  # decorative furniture only
  label_col <- "#41566f"
  muted_col <- "#5d6b7d"

  base <- ggplot2::theme(
    line = ggplot2::element_line(colour = "#000000", linewidth = base_line_size),
    rect = ggplot2::element_rect(fill = "#FFFFFF", colour = "#000000",
                                 linewidth = base_rect_size),
    text = ggplot2::element_text(family = base_family, colour = "#000000",
                                 size = base_size),
    plot.title = ggplot2::element_text(face = "bold", hjust = 0,
                                       size = ggplot2::rel(1.4),
                                       margin = ggplot2::margin(8, 0, 6, 0),
                                       colour = title_col),
    plot.subtitle = ggplot2::element_text(hjust = 0, size = ggplot2::rel(1.1),
                                          margin = ggplot2::margin(2, 0, 0, 0),
                                          colour = label_col),
    plot.caption = ggplot2::element_text(hjust = 1, size = ggplot2::rel(0.8),
                                         margin = ggplot2::margin(6, 0, 0, 0),
                                         colour = muted_col),
    axis.text.y = ggplot2::element_text(colour = muted_col, size = ggplot2::rel(0.9)),
    axis.title.y = ggplot2::element_text(colour = label_col,
                                         margin = ggplot2::margin(0, 4, 0, 0)),
    axis.text.x = ggplot2::element_text(colour = muted_col, size = ggplot2::rel(0.9)),
    axis.title.x = ggplot2::element_text(colour = label_col,
                                         margin = ggplot2::margin(4, 0, 0, 0)),
    panel.background = ggplot2::element_rect(fill = "white", colour = NA),
    strip.background = ggplot2::element_rect(fill = "#e9e9e9", colour = NA),
    strip.text = ggplot2::element_text(face = "bold", colour = "#2c4977",
                                       size = ggplot2::rel(1.0)),
    panel.border = ggplot2::element_blank(),
    axis.line = ggplot2::element_line(linewidth = base_line_size, colour = "black"),
    legend.position = "right"
  )

  grid_col <- "#dedddd"
  if (axis_type == "continuous") {
    grid_theme <- ggplot2::theme(
      panel.grid.major.y = ggplot2::element_line(colour = grid_col),
      panel.grid.major.x = ggplot2::element_line(colour = grid_col)
    )
  } else {
    grid_theme <- ggplot2::theme(
      panel.grid.major.y = ggplot2::element_line(colour = grid_col),
      panel.grid.major.x = ggplot2::element_blank()
    )
  }

  base + grid_theme
}

# ---- Brand-seeded palette constructors ---------------------------------------
# These wrap colorspace HCL generators, seeded on the current brand colour, so
# the ramp is perceptually based with monotonic luminance. With no set_brand()
# call the seed is teal; callers may also pass `base`/`low`/`high` explicitly,
# which always overrides the brand state. If no brand is intended at all, use
# colorspace::scale_*_{qualitative,sequential,diverging} directly.

#' Hue (HCL) of a colour, for seeding colorspace generators
#' @keywords internal
.hue_of <- function(col) {
  hcl <- colorspace::coords(as(colorspace::hex2RGB(.as_hex(col)), "polarLUV"))
  unname(hcl[, "H"])
}

#' Brand-seeded sequential scale (colour)
#'
#' Single-hue sequential ramp seeded on `base`, generated in HCL so luminance is
#' monotonic. Light-to-dark by default.
#'
#' @param base Seed colour. Defaults to the current `brand_base()`.
#' @param n Number of interpolation stops. Default 7.
#' @param ... Passed to `ggplot2::scale_colour_gradientn()`.
#' @return A ggplot2 scale.
#' @export
scale_colour_brand_seq <- function(base = brand_base(), n = 7, ...) {
  cols <- colorspace::sequential_hcl(
    n = n, h = .hue_of(base), c = c(70, 10), l = c(25, 95), power = 1.2,
    rev = TRUE
  )
  ggplot2::scale_colour_gradientn(colours = cols, ...)
}

#' @rdname scale_colour_brand_seq
#' @export
scale_fill_brand_seq <- function(base = brand_base(), n = 7, ...) {
  cols <- colorspace::sequential_hcl(
    n = n, h = .hue_of(base), c = c(70, 10), l = c(25, 95), power = 1.2,
    rev = TRUE
  )
  ggplot2::scale_fill_gradientn(colours = cols, ...)
}

#' Brand-seeded diverging scale (colour)
#'
#' Two-hue diverging ramp seeded on `low` and `high`, generated in HCL with a
#' balanced neutral midpoint. Supply `midpoint` to centre on a meaningful value.
#'
#' @param low Seed colour for the low arm. Defaults to navy or, after
#'   `set_brand()`, to the brand's complementary hue (or its `div_low`).
#' @param high Seed colour for the high arm. Defaults to the current `brand_base()`.
#' @param midpoint Data value mapped to the neutral midpoint. Default 0.
#' @param n Number of interpolation stops (odd recommended). Default 11.
#' @param ... Passed to `ggplot2::scale_colour_gradientn()`.
#' @return A ggplot2 scale.
#' @export
scale_colour_brand_div <- function(low = .brand_state$div_low,
                                    high = brand_base(),
                                    midpoint = 0, n = 11, ...) {
  cols <- colorspace::diverging_hcl(
    n = n, h = c(.hue_of(low), .hue_of(high)),
    c = 80, l = c(35, 95), power = 1.0
  )
  ggplot2::scale_colour_gradientn(
    colours = cols, rescaler = ~ scales::rescale_mid(.x, mid = midpoint), ...
  )
}

#' @rdname scale_colour_brand_div
#' @export
scale_fill_brand_div <- function(low = .brand_state$div_low,
                                  high = brand_base(),
                                  midpoint = 0, n = 11, ...) {
  cols <- colorspace::diverging_hcl(
    n = n, h = c(.hue_of(low), .hue_of(high)),
    c = 80, l = c(35, 95), power = 1.0
  )
  ggplot2::scale_fill_gradientn(
    colours = cols, rescaler = ~ scales::rescale_mid(.x, mid = midpoint), ...
  )
}

#' Qualitative scale (colour) for categorical groups
#'
#' Categorical palettes are NOT brand-seeded. A single brand colour cannot
#' generate a coherent, CVD-safe multi-hue set: spreading hues from one anchor
#' discards the seed's own chroma and luminance and walks through arbitrary
#' intermediate hues. This constructor therefore delegates to `colorspace`'s
#' `Dark 2` qualitative palette, which is built for mutual distinctness and is
#' CVD-tested, and which sizes itself to the number of groups (so it cannot raise
#' "Insufficient values in manual scale"). Reserve the brand colour for the
#' sequential ramp, the diverging high arm, and single-colour or highlight geoms,
#' where one seed genuinely works. Always pair with a redundant aesthetic (shape
#' or linetype).
#'
#' @param ... Passed to `colorspace::scale_colour_discrete_qualitative()`.
#' @return A ggplot2 scale.
#' @export
scale_colour_brand_qual <- function(...) {
  colorspace::scale_colour_discrete_qualitative(palette = "Dark 2", ...)
}

#' @rdname scale_colour_brand_qual
#' @param ... Passed to `colorspace::scale_fill_discrete_qualitative()`.
#' @export
scale_fill_brand_qual <- function(...) {
  colorspace::scale_fill_discrete_qualitative(palette = "Dark 2", ...)
}

#
# ADAPT: `fig1` is your existing ggplot. `panel_yrange()` reads layer 1 by
# default, which must be the geom whose data the brackets sit above (e.g. the
# boxplot). If layer 1 is a reference line or similar, pass the correct index,
# e.g. panel_yrange(fig1, layer = 2L).

emm <- emmeans::emmeans(model, specs = "group")

# lowest and highest y values drawn by one layer ----
panel_yrange <- function(p, layer = 1L) {
  d <- ggplot2::ggplot_build(p)$data[[layer]]
  # positional y columns ggplot may compute
  cols <- intersect(
    c("ymin_final", "ymin", "lower", "ymax_final", "ymax", "upper", "y"),
    names(d)
  )
  if (length(cols) == 0L) {
    stop("No y-position column found in layer ", layer, ".")
  }
  range(unlist(d[cols]), na.rm = TRUE)
}

y_range <- panel_yrange(fig1)
# step between brackets as a fraction of the data range, so positions work for
# negative values and for data far from zero
y_step <- 0.07 * diff(y_range)

contrasts_df <-
  pairs(emm, adjust = "tukey") |>
  as_tibble() |>
  separate_wider_delim(
    contrast, delim = " - ", names = c("group1", "group2")
  ) |>
  # emmeans wraps level names containing spaces or operators in parentheses
  dplyr::mutate(dplyr::across(
    c(group1, group2), \(x) stringr::str_remove_all(x, "^\\(|\\)$")
  )) |>
  dplyr::filter(p.value < 0.05) |>
  dplyr::mutate(
    p.label = scales::label_pvalue()(p.value),
    y.position = y_range[2] + y_step * dplyr::row_number()
  )

# headroom so the top bracket isn't clipped: highest position + one more step
y_top <- y_range[2] + y_step * (nrow(contrasts_df) + 1)

fig1 +
  stat_pvalue_manual(
    contrasts_df, label = "p.label", tip.length = 0.01
  ) +
  coord_cartesian(ylim = c(NA, y_top))

Glossary

term definition
canary A fixed line that an instruction file asks the assistant to include in its output, so that seeing the line shows the file was loaded. It does not show that the other rules were followed.
front matter The block between two lines of three dashes at the top of a file, holding settings such as a skill's name and description, or a Quarto document's options.
instruction file A file the assistant loads into every conversation, such as AGENTS.md or CLAUDE.md, stating the project's standing conventions. Its contents are requests, not guarantees.
skill A folder containing a SKILL.md file (and optionally scripts and templates) that an assistant loads only when it is invoked by name or judged relevant from its description.
symbolic link A file-system entry that points to another folder or file, so one copy can appear in two places. On Windows, copying the folder is usually simpler.
