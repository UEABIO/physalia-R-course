Setting up Claude Code

Claude Code is an AI agentAn assistant that can read across a project’s files and, depending on its permission mode, edit them and run commands, such as Claude Code. An agent acts; a chat window only advises. that runs in the Terminal tab of RStudio or Positron. It reads, edits and runs the files in your project, asking your permission as it goes. You need very little terminal: one command to start it, and the R console and Git pane for everything else.

⏱ 45–60 minutes, before the workshop day (most of it waiting for packages to install). You need a Claude account for Claude Code and, for Block 6, an Anthropic API key with a little prepaid credit (Step 7). If a command here fails, check the Claude Code setup page first.

Before you install: three questions

  1. Are you permitted to use it on this work? Claude Code sends what it reads, and the output of commands it runs, to Anthropic. Check your institution’s policy and, near research data, your ethics approval and data agreements (Block 3).
  2. Which account? A Claude Pro or Max subscription, a Claude Team or Enterprise seat, a Claude Console account (billed per request), or access your institution has set up through a cloud provider.
  3. Is your computer supported? macOS 13 or later, Windows 10 (1809) or later, or a recent Linux.

Step 1: Open the Terminal tab in your IDE

  • RStudio: the Terminal tab next to the Console.
  • Positron: Terminal → New Terminal.

With a project open, the Terminal tab starts in the project’s root folder, which is where Claude Code needs to run. You never need to cd.

Which shell is it? A prompt starting PS is PowerShell (Windows); one ending $ is Git Bash (Windows) or bash/zsh (macOS, Linux).

Step 2: Check git and R are reachable

In the terminal:

git --version
Rscript --version

Both should print a version number.

  • git not found: install git (on Windows, Git for Windows).
  • Rscript not found (common on Windows): run R.home("bin") in the R console and add that folder to your PATH (Windows: Start menu → “Edit environment variables for your account” → Path). Then quit and reopen RStudio or Positron: its terminals keep the PATH they started with.

Step 3: Install Claude Code

macOS or Linux, in the terminal:

curl -fsSL https://claude.ai/install.sh | bash

Windows, in PowerShell (a prompt starting PS; if your Terminal tab is Git Bash, open the PowerShell app for this one step):

irm https://claude.ai/install.ps1 | iex

Then quit and reopen RStudio or Positron, and check the version in the Terminal tab:

claude --version

You are done when it prints 2.1.281 or later. This minimum is about your instruction file: by this version, Claude Code reads your AGENTS.md directly and lists it in /memory.

Step 4: Prepare your workshop repository

Do this before you sign in, so that Claude Code starts in the right folder.

  1. Fork, clone and open the template in one step, in the R console: usethis::create_from_github("<template-owner>/<template-repo>", fork = TRUE). Your instructor gives you the exact name.
  2. Restore the packages: renv::restore() in the R console, once. It installs the versions in the template’s lockfileThe renv.lock file that records the R version and the exact package versions a project uses, so renv::restore() can rebuild the same environment. and can take several minutes.
  3. Start clean. If the Git pane (RStudio) or Source Control view (Positron) shows any changed file, commit it, so the day starts with no changes.

The course skillsA folder containing a SKILL.md file (and optionally scripts and templates) that an assistant loads only when it is invoked by name or judged relevant from its description. already ship in both .agents/skills/ and .claude/skills/.

TipUsing Posit Assistant

Posit Assistant needs no terminal install: it is built into RStudio and Positron and configured there. Check that your account or provider key works before the day; Block 3 lists the options.

Step 5: Sign in

With your workshop repository open, type claude in its Terminal tab. On first launch a browser window opens: sign in with your account (/logout and /login switch accounts later). If a Terminal tab was open before you switched projects, close it and open a new one.

WarningUsing an API key

If you use a Console API key, set it as ANTHROPIC_API_KEY, for example in .Renviron, and never commit that file. The template denies Claude Code reading a .Renviron in the project folder, but not the one in your home folder. If ANTHROPIC_API_KEY is already set for another tool, Claude Code may use it instead of your subscription and bill per request: check under /config.

Step 6: The essentials

Your workshop repository starts Claude Code in Manual mode (default), a permission modeThe setting that decides how much Claude Code may do without asking: plan (read only), default (asks before edits and commands), acceptEdits (edits without asking) and bypassPermissions (never asks). in which it asks before every edit and command. Claude Code’s own default is auto, where a second model approves actions for you; the project setting overrides it. Read each request, and answer with plain Yes or No: never choose an option that says don’t ask again, which saves a rule that skips the question from then on. Shift+Tab changes the mode, /plan asks for a plan first, and the Claude Code quick reference lists the rest.

Where am I typing?

Where What runs there
The Claude Code prompt, inside the Terminal tab Your requests to Claude Code. A line starting ! runs a shell command, and its output is added to the conversation, so it reaches the model too.
The terminal’s own prompt (PS, $ or %), after /exit Shell commands: claude, git, Rscript
The R console R code. Claude Code cannot see it, or anything you load there.
The Git pane (RStudio) or Source Control view (Positron) Git status, diffs, reverting and committing, on the same repository

While Claude Code is running, the Terminal tab belongs to it, so check its work somewhere else.

Checking work while Claude Code is running

To check… In the R console or Git pane
What changed The Git pane: Diff shows the changes line by line; Revert undoes one you did not want.
That a script runs in a fresh R session Session → Restart R, then source(here::here("scripts", "name.R"))
That the tests pass in a fresh R session Session → Restart R, then testthat::test_dir(here::here("tests"))
That the packages match the lockfile renv::status()

These work the same on Windows, macOS and Linux. Each Rscript call Claude Code makes is a fresh R process too, so objects never carry over to it from your console.

NoteAt the command line

The same checks from a terminal (after /exit, or in a second Terminal tab): git status, git diff, git restore <file>, Rscript scripts/name.R, Rscript -e "testthat::test_dir('tests')" and Rscript -e "renv::status()".

Step 7: An API key for Block 6

In Block 6 you build your own agent in R with the ellmer package. It calls Claude through the Anthropic API, which is billed per request and is separate from a Claude Pro or Max subscription.

  1. Get a key. Create an account at https://console.anthropic.com, add a little prepaid credit (check the current prices on Anthropic’s pricing page; the block needs only a few dozen requests), and create an API key.

  2. Save it outside every project. In the R console, run usethis::edit_r_environ(), which opens your user-level .Renviron, and add one line:

    AGENT_ANTHROPIC_KEY=your-key-here

    Save the file and restart R. The name is deliberate: Claude Code looks for ANTHROPIC_API_KEY, and would offer to bill that key instead of your subscription. Never paste a key into a script.

  3. Test it. In the R console:

    ellmer::chat_anthropic(
  model = "claude-sonnet-5-5",
  credentials = \() Sys.getenv("AGENT_ANTHROPIC_KEY")
)$chat("Reply with the word OK.")

You are done when the model replies. If it reports a missing or invalid key, check the line in .Renviron and restart R.

  • Positron: choose GitHub Copilot as the completions provider, and sign in with your GitHub account when Positron prompts you, or from its AI assistant settings.

To check it, type # Calculate the mean of 1 to 100 in a new, unsaved R script: grey suggested text should appear.

Step 8: Check everything works

Pre-workshop check (15 minutes)

Goal: confirm that Claude Code, R, your repository and your API key all work, so that the day starts with the first block rather than with set-up problems.

Start state: your workshop repository is open, and the Git pane shows no uncommitted changes.

1. Manual mode. Type claude in the Terminal tab. It should say it is in Manual mode (default), not auto. Then:

Describe what each top-level folder of this repository contains. Do not
change anything.

It should answer without asking to edit anything.

2. R is reachable.

Run Rscript -e "sessionInfo()" and show me the output.

Approve the command when asked: you should see your R version.

3. Settings and instructions load. /permissions should list 17 deny rules, and /memory should list AGENTS.md. On a Pro or Max account, also open /privacy-settings and decide whether your conversations may be used for model training. Type /exit.

4. The project is ready. Restart R (Session → Restart R), then in the R console:

renv::status()
testthat::test_dir(here::here("tests"))

renv::status() should report no problems, and the test summary should show FAIL 0 and PASS 8: the eight passing checks cover the protections, Manual mode, no command approved in advance, AGENTS.md, git and the raw-data checksum. The other tests skip, waiting for the block that creates their files.

5. The agent’s model answers. You did this in Step 7; if you skipped it, do it now, because Block 6 needs it.

6. The checkpoint branches are there. The Git pane’s branch menu should show checkpoint-skills, checkpoint-cleaning and checkpoint-refactor. Stay on main.

7. The code-review folder. Block 9 reviews the Day 2 script in a folder of its own. In the R console:

review_dir <- usethis::create_project("~/ai-review", open = FALSE)
download.file("https://osf.io/download/3x6hb/",
              file.path(review_dir, "ANALYSIS.R"), mode = "wb")

It prints where it made the folder; check ANALYSIS.R is there. If the download fails, download ANALYSIS.R from the OSF project in your browser into that folder.

You are done when the Git pane shows no changes, Claude Code starts in Manual mode, /permissions lists 17 deny rules, the tests run with no failures, the API key test replies, and ~/ai-review holds ANALYSIS.R. If anything differs, copy the output of steps 2 and 4 into a note outside the repository and bring it on the day.

If it goes wrong: Rscript not found, return to Step 2; no reply from the API key test, return to Step 7; empty /permissions list, start claude from the workshop repository’s Terminal tab; a changed file, Revert in the Git pane; package problems, run renv::restore() again and send the error to your instructor before the day.

Glossary

term definition
agent An assistant that can read across a project's files and, depending on its permission mode, edit them and run commands, such as Claude Code. An agent acts; a chat window only advises.
deny rule A permission rule in the deny list of .claude/settings.json that stops Claude Code's built-in tools from editing or reading the matching files. It checks shell output redirects such as > file, but not R code or most other commands that change the same files.
lockfile The renv.lock file that records the R version and the exact package versions a project uses, so renv::restore() can rebuild the same environment.
permission mode The setting that decides how much Claude Code may do without asking: plan (read only), default (asks before edits and commands), acceptEdits (edits without asking) and bypassPermissions (never asks).
skill A folder containing a SKILL.md file (and optionally scripts and templates) that an assistant loads only when it is invoked by name or judged relevant from its description.
symbolic link A file-system entry that points to another folder or file, so one copy can appear in two places. On Windows, copying the folder is usually simpler.
