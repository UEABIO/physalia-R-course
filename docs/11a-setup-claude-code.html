Setting up Claude Code

Installation details change. If a command here fails, check the Claude Code setup page first.

Claude Code is an AI agentAn assistant that can read across a project’s files and, depending on its permission mode, edit them and run commands, such as Claude Code. An agent acts; a chat window only advises. that runs in a terminal. It reads the files in the folder you start it from, edits them, and runs commands, including R scripts, asking your permission as it goes. Most participants at this level have not used a terminal much. This chapter covers the minimum you need, and ends with a check that everything works before the workshop day.

⏱ ~30 minutes, best done before the workshop

Before you install: three questions

  1. Are you permitted to use it on this work? Claude Code sends the files it reads, and the output of commands it runs, to Anthropic. Check your institution’s policy, and your ethics approval and data agreements if you will use it near research data. Block 4 covers this in detail.
  2. Which account will you use? You need one of:
    • a Claude Pro or Max subscription, signing in with your Claude.ai account;
    • a Claude for Teams or Enterprise seat, if your institution provides one;
    • a Claude Console account, which bills API use per request;
    • access through a cloud provider (Amazon Bedrock, Google Vertex AI or Microsoft Foundry), if your institution has set this up.
    Check current prices on Anthropic’s pricing page before you choose.
  3. Is your computer supported? Claude Code requires macOS 13 or later, Windows 10 (version 1809) or later, or a recent Linux distribution.

Step 1: Open a terminal

You can use the terminal built into your IDE, which starts in your project folder:

  • RStudio: Tools → Terminal → New Terminal, or the Terminal tab beside the Console.
  • Positron or VS Code: Terminal → New Terminal.

Or use your system’s terminal: Terminal on macOS, PowerShell on Windows.

Step 2: Check git and R are reachable

Claude Code runs R by calling Rscript, and it works best in a git repository.

In the terminal:

git --version
Rscript --version

Both should print a version number.

  • git not found: install git. On Windows, install Git for Windows, which Claude Code also uses as its shell.
  • Rscript not found (common on Windows): the R installer does not always add R to your system path. Add R’s bin folder (for example C:\Program Files\R\R-4.5.2\bin) to your PATH environment variable, open a new terminal, and try again.

Step 3: Install Claude Code

macOS, Linux, or WSL on Windows. In the terminal:

curl -fsSL https://claude.ai/install.sh | bash

Windows, in PowerShell (the terminal Step 1 suggests):

irm https://claude.ai/install.ps1 | iex

Windows, in Command Prompt (alternative):

curl -fsSL https://claude.ai/install.cmd -o install.cmd && install.cmd && del install.cmd

If you see The token '&&' is not a valid statement separator, you ran the Command Prompt line in PowerShell: use the PowerShell line instead.

macOS with Homebrew (alternative). In the terminal:

brew install --cask claude-code

Open a new terminal, then confirm the installation.

In the terminal:

claude --version

The native installer keeps Claude Code up to date in the background. Homebrew and other package-manager installations need to be updated by hand.

Before you sign in: prepare your workshop repository

Set-up takes time on the day, so do these once beforehand. Step 6 then checks the result.

  1. Fork the workshop template on GitHub, clone your fork, and open it as a project in your IDE.
  2. Restore the packages. In the R console, run renv::restore() once. It installs the package versions recorded in the template’s lockfileThe renv.lock file that records the R version and the exact package versions a project uses, so renv::restore() can rebuild the same environment., and can take several minutes.
  3. Check the skills folder. Claude Code reads skillsA folder containing a SKILL.md file (and optionally scripts and templates) that an assistant loads only when it is invoked by name or judged relevant from its description. from .claude/skills/. If your fork has skill folders in .agents/skills/ but they are not already present in .claude/skills/, copy each skill folder across, so that, for example, .claude/skills/clean-with-codebook/SKILL.md exists. Copying is the simplest route and works on every system. On macOS or Linux you can instead create a symbolic linkA file-system entry that points to another folder or file, so one copy can appear in two places. On Windows, copying the folder is usually simpler., as Block 5 describes, so there is only one copy to keep up to date.
  4. Commit, so that your fork has no uncommitted changes when the day starts.
TipUsing Posit Assistant

Posit Assistant needs no terminal install: it is built into RStudio and Positron, and you configure it there. It reads skills from .agents/skills/ directly, so step 3 is not needed. Check that your account or provider key works before the day; the access note in Block 4 lists the options.

Step 4: Sign in

Start Claude Code from your workshop repository’s root folder.

In the terminal:

cd path/to/your/workshop-repository
claude

On first launch, Claude Code opens a browser window. Sign in with the account you chose above. To switch accounts later, use /logout and /login inside Claude Code.

Warning

API keys. If you use a Console API key, set it as the environment variable ANTHROPIC_API_KEY. Many R users keep keys in .Renviron. Never commit that file. Add it to .gitignore. The template’s settings already include the deny rule Read(/.Renviron) (see Block 6), but it covers only a .Renviron in the project folder, not the one in your home folder.

If ANTHROPIC_API_KEY is already set for another tool, such as Posit Assistant, Claude Code may use it instead of your subscription, and you will be billed per request. Check which credential is in use under /config.

Step 5: Learn five things

To… Do this
Start in your workshop repository cd to its root folder, then claude
Change how much it may do without asking Shift+Tab cycles default → acceptEdits → plan
Start in read-only planning mode claude --permission-mode plan
See which permission rules are active /permissions
Leave /exit, or close the terminal

Each of these settings is a permission modeThe setting that decides how much Claude Code may do without asking: plan (read only), default (asks before edits and commands), acceptEdits (edits without asking) and bypassPermissions (never asks).. Every time it wants to edit a file or run a command in default mode, Claude Code asks first. Read each request before you approve it. The autonomy ladder in Block 4 explains what each mode allows, and the full Claude Code quick reference in Block 1 adds how to interrupt it, approve a plan and start a new conversation.

Always start Claude Code from your workshop repository’s root folder. It works on the folder it starts in, and your project settings in .claude/settings.json are found relative to it.

Step 6: Check everything works

Pre-workshop check (10 minutes)

Do this in your workshop repository, with no uncommitted changes.

1. Read-only. Start in plan mode.

In the terminal:

claude --permission-mode plan

Prompt (Claude Code):

Describe the structure of this repository and what each top-level folder
contains. Do not change anything.

Type /exit, then run git status in the terminal. Nothing should have changed.

2. R is reachable. Start claude again, in default mode.

Prompt (Claude Code):

Run Rscript -e "sessionInfo()" and show me the output.

Approve the command when asked. You should see your R version and loaded packages. If Claude Code reports that Rscript was not found, return to Step 2.

3. Project settings load. Type /permissions. The deny rules from .claude/settings.json, which ships with the template, should be listed. If the list is empty, check that you started claude from the repository’s root folder.

4. Bring evidence. Copy the output of steps 2 and 3 into a text file and bring it to the workshop. If any step failed, note the error message exactly.

Glossary

term definition
agent An assistant that can read across a project's files and, depending on its permission mode, edit them and run commands, such as Claude Code. An agent acts; a chat window only advises.
deny rule A permission rule in the deny list of .claude/settings.json that stops Claude Code's built-in tools from editing or reading the matching files. It checks shell output redirects such as > file, but not R code or most other commands that change the same files.
lockfile The renv.lock file that records the R version and the exact package versions a project uses, so renv::restore() can rebuild the same environment.
permission mode The setting that decides how much Claude Code may do without asking: plan (read only), default (asks before edits and commands), acceptEdits (edits without asking) and bypassPermissions (never asks).
skill A folder containing a SKILL.md file (and optionally scripts and templates) that an assistant loads only when it is invoked by name or judged relevant from its description.
symbolic link A file-system entry that points to another folder or file, so one copy can appear in two places. On Windows, copying the folder is usually simpler.
