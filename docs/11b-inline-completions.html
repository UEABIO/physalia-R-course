Block 2: Inline completions

Inline completion is the simplest kind of assistantAny AI tool that helps you write or understand code, from inline completion to a chat window. In this course “assistant” is the general word; “agent” is used when the tool acts on your files.: grey “ghost text” appears as you type, and you accept it with Tab, reject it with Esc, or carry on typing. By the end of this block you will know how to get useful suggestions every time: write a specific comment just before the cursor.

Claude Code has no inline completion, so this is the one block where GitHub Copilot is the main tool.

⏱ ~25 minutes

Setup

You signed in to GitHub Copilot in the pre-work (Setting up Claude Code, Step 7). Check it still works: in a blank R script, type # Calculate the mean of 1 to 100. Within a few seconds you should see ghost text such as mean(1:100); if not, press Enter and wait.

If no ghost text appears, follow the instructor’s screen for this block and fix the set-up at the break.

NoteSet-up routes, plans and data
  • RStudio: enable GitHub Copilot in RStudio’s options and sign in to GitHub.
  • Positron: choose GitHub Copilot as the completions provider (see Positron’s completions documentation).
  • VS Code: select Use AI Features from the Copilot icon in the Status Bar and sign in with GitHub.

Copilot Free allows a limited number of completions per month (2,000 at the time of writing); paid plans do not meter them. Completions send the code around your cursor to the provider, so the disclosure points in Block 4 apply here too. Use one completion provider at a time, so you know which tool made each suggestion.

TipUsing Posit Assistant

In RStudio and Positron you can use Posit AI Next Edit Suggestions instead: in RStudio, turn it on from the Posit Assistant toolbar button (it needs a Posit AI account); in Positron, choose it as the completions provider. Posit AI does not meter completions.

The context principle

A suggestion can only use what is in the model’s context windowThe maximum amount of text a language model can consider in one call. The model has no memory between calls, so it sees only what is in the context window. when it is made. Copilot fills that window mainly from the current file, and above all from the comment just before the cursor. In Positron and VS Code it may also use other open tabs. It does not see your R session.

TipUsing Posit Assistant

Posit AI Next Edit Suggestions also sees your live R session: the columns of loaded data frames, the functions you have defined and the packages you have loaded. What you have loaded becomes one more lever.

Activity: The context demonstration

The context demonstration (10 minutes)

Start state: your workshop repository is open, and the set-up check produced ghost text.

The data are voles_metabolism.csv: a synthetic trial in 72 voles, with columns subject_id, sex, treatment_arm, mass_pre_g, mass_post_g and metabolic_rate_post. The names were chosen so that no model has seen them before.

1. No context. Restart R, so you are in a fresh R sessionAn R session with nothing loaded from earlier work: Session > Restart R in RStudio or Positron (with “never save .RData” set, as on Day 1), callr::rscript() from the console, or Rscript in the terminal. Code that only works in your current session depends on something you did not record., and open a blank R script. Type only this comment, and wait.

In the R script:

# calculate the mean change in mass by treatment

Note the suggestion. With no data and no column names in view, the model has to guess.

2. Context in the file. In a new blank script, type the lines below down to glimpse(voles), and run them, so that voles is loaded. Then type the same comment on a new line, and wait.

In the R script:

# Voles metabolism trial: effect of treatment on body mass
# 72 voles, three treatment arms (Control, Low_dose, High_dose), two sexes
# Native pipe |>, tidyverse

library(tidyverse)

voles <- read_csv(here::here("data", "raw", "voles_metabolism.csv"))
glimpse(voles)

# calculate the mean change in mass by treatment
voles |>
  mutate(mass_change_g = mass_post_g - mass_pre_g) |>
  summarise(
    mean_change = mean(mass_change_g, na.rm = TRUE),
    .by = treatment_arm
  )

The exact form varies between people and sessions.

Compare the two suggestions. Did the second use real column names? Did it compute post minus pre?

You are done when you can say what the second suggestion had that the first did not.

If it goes wrong: if no suggestion appears, type the comment again on a new line; if the script stops running, Session → Restart R and run it from the top.

TipUsing Posit Assistant: context in the session

With Posit AI Next Edit Suggestions, keep voles loaded from step 2, then type only the comment from step 1 in a new blank script. If the suggestion now uses the real column names, it came from your session, not from the file.

Activity: Build a small analysis

Build a small analysis (10 minutes)

Start state: the script from step 2, with voles loaded.

For each step, write the comment first, then accept, modify or reject the suggestion, and note which you did. The note is what makes you notice an unchecked acceptance.

1. Summary table. The mean and standard deviation of mass_change_g by treatment_arm and sex, with the number of observations per cell. (Create mass_change_g first if your script does not have it.)

2. Plot. mass_change_g against metabolic_rate_post, coloured by treatment_arm.

You are done when a fresh R session (Session → Restart R, then run the script from the top) produces the table and the plot without error.

If it goes wrong: delete the last suggestion you accepted, and write a more specific comment naming the data frame and its columns.

# Voles metabolism trial: effect of treatment on body mass
library(tidyverse)
library(here)

voles <- read_csv(
  here("data", "raw", "voles_metabolism.csv"),
  col_types = cols(
    subject_id = col_character(),
    sex = col_character(),
    treatment_arm = col_character(),
    mass_pre_g = col_double(),
    mass_post_g = col_double(),
    metabolic_rate_post = col_double()
  )
) |>
  mutate(mass_change_g = mass_post_g - mass_pre_g)

# mean and SD of mass_change_g by treatment_arm and sex, with n per cell
voles |>
  summarise(
    mean_change_g = mean(mass_change_g),
    sd_change_g = sd(mass_change_g),
    n = n(),
    .by = c(treatment_arm, sex)
  ) |>
  arrange(treatment_arm, sex)

# mass_change_g against metabolic_rate_post, coloured by treatment_arm
ggplot(voles, aes(metabolic_rate_post, mass_change_g, colour = treatment_arm)) +
  geom_point() +
  labs(x = "Metabolic rate (post-treatment)", y = "Change in mass (g)")

The plot drops the one animal with no metabolic rate and says so in a warning: read it rather than ignore it.

NoteCheck · Reproduce · Record
  • You can now: steer inline completion with a specific comment and the right code above the cursor, trusted because you decided on every suggestion and the script runs from a fresh R session.
  • Check: accept, modify or reject every suggestion deliberately.
  • Reproduce: good suggestions come from context in the file or session, so keep that context in the script, where it reruns.
  • Record: nothing to log yet; your AI-use logA record written at the time of each piece of AI-assisted work, in the form: date; tool and model; task; what you kept or changed. TipThe full four-step analysis

The live activity uses two of four steps. The full sequence, again writing the comment for each step before accepting, rejecting or modifying the suggestion:

  1. Filter to subjects with non-missing metabolic_rate_post and create a derived variable mass_change_g.
  2. Produce a summary table of the mean and standard deviation of mass_change_g by treatment_arm and sex, with the number of observations per cell.
  3. Fit a linear model of metabolic_rate_post on treatment_arm and sex. Inspect the coefficients.
  4. Produce one plot relating mass_change_g to metabolic_rate_post, coloured by treatment_arm.

When you have finished steps 2 and 4, post the code Copilot suggested for step 4 in the Zoom chat, with a note on whether you accepted, changed or rejected it. Then compare with what others posted: the comparison usually shows different suggestions, different acceptance decisions and, often, different bugs.

Glossary

agent An assistant that can read across a project's files and, depending on its permission mode, edit them and run commands, such as Claude Code. An agent acts; a chat window only advises.
AI-use log A record written at the time of each piece of AI-assisted work, in the form: date; tool and model; task; what you kept or changed. It becomes the AI declaration in a README.
