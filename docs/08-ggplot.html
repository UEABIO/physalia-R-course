How we see data

Our visual system did not evolve to read graphs. Some visual features are detected before conscious attention engages: a red dot among grey dots, a single triangle in a sea of circles, an unusually large shape in a field of small ones. This is called pre-attentive processing (Healey and Enns, 2012). If you encode important information as a feature the eye picks up automatically, readers see it without having to search. Encoding the same information as a subtle change in line style or a slightly different shade requires the reader to look for it.

You have just played a version of Cleveland and McGill’s (1984) experiment (they tested bars and pie slices; Rounds 3 and 4 go further). People read the same ratio most accurately as position on a common scale, then length, angle, area, and last shading and colour saturation. Mackinlay (1986) extended the ranking to categorical data: position is still best, but colour hue rises to second. Shape is weaker but useful as a redundant cue.

The encoding hierarchy

The practical rule is: assign your most important variable to the highest-ranked encoding available to you. For two continuous variables, both go to position (a scatter plot). For a continuous variable grouped by a category, position handles the continuous variable and colour hue handles the category, with shape added redundantly for accessibility.

  • Colour
  • Shape
  • Both

Two continuous variables to position (rank 1), one categorical to colour hue (rank 2 for categorical data), with shape added as a redundant cue. The figure works on a colour monitor, in greyscale print, and for a reader with colour vision deficiency. Treat this as the minimum for every figure.

Colour as a tool

Colour hue is the second-most powerful encoding for categorical data, and it is pre-attentive, so readers pick it up without searching. It is also the encoding most often misused. Three palette types exist, each for a different data structure:

Palette type Data structure Example use
Qualitative Discrete groups with no inherent order Species, treatment arm
Sequential Continuous, running in one direction from a minimum Gene expression, density
Diverging Continuous, with a meaningful midpoint Log fold-change, temperature anomaly

Using the wrong type for the data structure is one of the most common errors. A sequential palette applied to categorical data implies an ordering that does not exist. A categorical palette applied to a continuous variable conceals the ordering that does exist.

The package colorspace (Zeileis et al., 2020) provides palette generators for all three types with documented design rationale, and is the project default for palette construction. The Dark2 palette ships directly:

# Categorical (Dark2): for discrete groups with no order
colorspace::swatchplot(
  colorspace::qualitative_hcl(8, palette = "Dark2")
)

The same package provides scale_*_discrete_qualitative(), scale_*_continuous_sequential(), and scale_*_continuous_diverging() functions that integrate directly with ggplot2. Prefer these over manual hex vectors.

Accessibility

Roughly 8% of men have some form of colour vision deficiency (Sharpe et al., 1999); red-green is by far the most common. Using red and green to distinguish two groups will fail for a non-trivial fraction of any audience. The Okabe-Ito palette was designed to remain distinguishable under deuteranopia and protanopia (Okabe and Ito, 2008), and the viridis palette family is perceptually uniform under colour vision deficiency and in greyscale.

Beyond palette choice, the main rule is redundant encoding: never let colour be the only cue distinguishing groups. Use shape redundantly for points, linetype redundantly for lines, and direct labelling wherever it is legible (we will cover direct labelling in Block 4).

The colorBlindness package gives you the verification step. colorBlindness::cvdPlot() produces, by default, a four-panel simulation: the original (“normal vision”), deuteranopia, protanopia, and a desaturated (greyscale) version. This lets you see whether the figure still works when colour fails. Extra “enhanced” panels can be requested through its layout argument; note that it does not simulate tritanopia.

fig <- penguins_complete |> 
  ggplot(aes(x = body_mass_g, y = flipper_length_mm, colour = species)) +
  geom_point(alpha = 0.7) +
  colorspace::scale_colour_discrete_qualitative(palette = "Dark2") +
  theme_minimal()

colorBlindness::cvdPlot(fig)

Data-ink ratio

Tufte (1983) introduced data-ink ratio: the proportion of a figure’s visual elements that actually encode data, as opposed to decoration, borders, gridlines, shadows, and three-dimensional effects that exist for their own sake. High data-ink ratio means most of the visual complexity of the figure carries information.

The default ggplot2 theme_grey() already fails this test: a grey panel background and white gridlines exist purely as decoration. Move to theme_minimal(), theme_classic(), or a project-specific theme function as your default.

Warning

Avoid theme_grey() (the ggplot2 default) in any figure intended for human consumption. Set theme_minimal(base_size = 12) or theme_classic(base_size = 12) as your project baseline.

Graph crimes

A figure that violates these principles distorts what the data actually say. Five recurring crimes are worth recognising on sight:

  1. Truncated bar chart axes. A bar encodes magnitude as length from a baseline. If the axis does not start at zero, the visual ratio between bars is no longer the data ratio.
  2. Manipulating the y-axis. Compressed or expanded vertical ranges can make tiny effects look enormous or hide real effects.
  3. Cherry-picking time ranges. Choosing a window of time that supports a story while ignoring the surrounding data.
  4. Wrong chart for the data. Pie charts for many categories; line charts for unordered categorical data; dual y-axes pretending two arbitrary scales are commensurable.
  5. Convention violations. Inverted colour scales (light = high); inverted y-axes; latitude on the x-axis. Readers bring expectations, and figures that violate them mislead.

A bonus crime: spurious correlation. Two variables with a strong correlation may have no causal relationship at all. Showing a strong correlation without acknowledging the confounders is a misrepresentation of evidence.

Exercise: fix a graph-crime scene

Fix the crime scene (12 minutes)

The code below was found at a crime scene. It uses chickwts, a dataset built into R: the weight of chicks after six weeks on one of six feed supplements. Copy it into RStudio and run it. There are at least eight graph crimes in it.

  1. Investigate (4 min). List every crime you can find, then post your list in Slack.
  2. Rehabilitate (8 min). Rewrite the code into an honest, accessible figure in your own RStudio.
  3. Check. Post a screenshot of your fixed figure in Slack, then go through the case file below: which crimes did you spot, which did you fix, and which did you miss? We’ll put a few fixed figures on screen and talk through the choices.
chickwts |>
  group_by(feed) |>
  summarise(mean_weight = mean(weight), se = sd(weight) / sqrt(n())) |>
  ggplot(aes(x = feed, y = mean_weight, fill = feed)) +
  geom_col() +
  geom_errorbar(aes(ymin = mean_weight - se, ymax = mean_weight + se), width = 0.2) +
  coord_cartesian(ylim = c(150, 350)) +
  scale_fill_manual(values = rainbow(6)) +
  labs(x = "feed", y = "mean_weight") +
  theme_grey()
  1. Dynamite plot. Bars of means hide the 71 individual chicks.
  2. Truncated axis. The bars start at 150 g, so horsebean looks a fraction of casein’s weight; the real ratio is about half.
  3. Undefined error bars. They are ± 1 SE, but nothing says so.
  4. Rainbow palette. Not colour-blind safe (red vs green), and the lightness jumps around.
  5. Redundant legend. Colour repeats the x-axis, so the legend is pure eye-travel.
  6. Unordered categories. Alphabetical order hides the ranking.
  7. Variable names as labels. “mean_weight” with no units.
  8. theme_grey(). The grey panel fails the data-ink test.
chickwts |>
  mutate(feed = fct_reorder(feed, weight, .fun = median)) |>
  ggplot(aes(x = weight, y = feed)) +
  geom_jitter(height = 0.15, alpha = 0.6, colour = "grey45") +
  stat_summary(fun = median, geom = "point", shape = 23,
               size = 3.5, fill = "#D95F02") +
  labs(x = "Chick weight at six weeks (g)", y = "Feed supplement",
       caption = "Points: individual chicks. Diamonds: medians.") +
  theme_minimal(base_size = 12) +
  theme(panel.grid.minor = element_blank())

Every chick is visible, the feeds are ranked, there is one colour with a job (the median), the axis has units, and no legend is needed. Because these are points rather than bars, the axis does not need to start at zero.
