Block 7: Data cleaning and validation with AI

Cleaning mistakes are silent: a missing-value code treated as a measurement, the same animal kept twice, a row quietly dropped. In this block an agent writes and runs the whole cleaning script from one command, and one test run tells you whether to trust it. You own the facts (the codebookA table describing each variable: its type, valid range, missing-value codes, unit and label mappings. It is the data dictionary from Day 2 with machine-readable rules, and you own it, not the AI.); everything else ships with the template:

Part Owner Why
Codebook (docs/codebook.csv) You Codes, units, ranges and labels are facts about how the data were collected, not something to infer from the values
Cleaning skill Template How to clean: never touch raw data, log every change, never drop a row silently
Tests and validation rules Template Written from the codebook, independently of the cleaning code
Deny rules Template Keep the agent’s edit tools off the raw data, the codebook, the data note and the tests

The cleaning and the checks both read the codebook but never each other, so a misunderstanding in one is caught by the other:

Facts first

data/raw/voles_raw.csv, pinned by a checksum

profiled in R

docs/profile.csv

plus the provider’s note

docs/codebook.csv

Two branches that read the codebook, never each other

Skill writes and runs scripts/01_clean.R

writes

Clean data, cleaning log, exclusion log

Validation rules in validate_voles.R, transcribed from the codebook

Then compare

One test run: raw data unchanged, every row accounted for, every change logged, the same answer every time

Independence is the point: one misunderstanding cannot pass both branches.

The voles data have errors planted in them; your instructor holds the answer key, so at the end you measure what your pipeline caught. The steps follow the safe vibe-coding recipe from Block 4.

⏱ ~50 minutes

Note

Why not simply ask a chatbot to clean the data? In a 2025 study, language models given polluted tables missed codes such as -1 (a sentinel valueA number with a special meaning, such as 9999 for “not recorded” or -1 for “run failed”. It must be documented in a codebook and recoded before analysis.) and rarely spotted near duplicates (Spreafico et al., 2025). Those error classes are planted here.

Step 0: Check the safeguards are in place

Recipe check (3 minutes)

Start: your workshop repository on main, Git pane clean (behind on Block 5? switch to block5-done in the Git pane’s branch menu).

1. The protections. Start claude and type /permissions. Look for these deny rulesA permission rule in the deny list of .claude/settings.json that stops Claude Code’s built-in tools from editing or reading the matching files. It checks shell output redirects such as > file, but not R code or most other commands that change the same files.: Edit(/data/raw/**), Read(/docs/data_note.md), Edit(/docs/codebook.csv), Edit(/tests/test_cleaning.R) and Edit(/tests/test_audit.R).

2. The checks. In the Files pane, tests/ holds test_cleaning.R, test_audit.R and fixtures/raw_checksum.txt (a checksumA short fingerprint computed from a file’s contents, for example with tools::md5sum(). Any change to the file changes the checksum, so it detects changes made by any route. of the raw file). The tests skip until clean data exist.

You are done when you have seen the five rules and the three files.

If it goes wrong: if /permissions lists no rules, check you started claude from the workshop project’s Terminal tab; if the files are missing, switch to block5-done.

Step 1: Profile the raw data

Profiling is counting, so R does it, not the model.

Profile (5 minutes)

In the R console:

source(here::here("scripts", "00_profile.R"))
View(readr::read_csv(here::here("docs", "profile.csv"), show_col_types = FALSE))

If it goes wrong: restart R (Session → Restart R) and run the line again.

Step 2: Draft the codebook with the agent, then audit it

The codebook is Day 2’s data dictionary (README chapter) with machine-readable rules. The agent drafts it from the data alone, because it cannot read the data provider’s note: just like an analyst who never asked for the note.

Draft and audit the codebook (12 minutes)

1. Ask for a draft.

Prompt (Claude Code):

/plan Draft docs/codebook.csv with the columns column, type, rule, min, max,
missing_codes, unit, source, from docs/profile.csv only. In the source
column, say for every entry whether it comes from the profile or is your
assumption. Show the CSV in your reply; do not write any file.

Read rules are best effort: if it proposes a command that would open the note, refuse it.

2. Save it yourself. usethis::edit_file("docs/codebook.csv") in the R console, paste, save. The agent is denied this file: the codebook is yours. (Avoid Excel, which can silently change quoted fields.)

3. Audit the draft. Before you open docs/data_note.md, answer:

  • Did the draft list 9999 as a missing-value code, or treat it as a large measurement?
  • Did it notice that -1 is a code?
  • Where did its min and max come from? A range read off the data includes its errors, so valid ranges must come from the biology or the protocol.

4. Correct it against the note. Open docs/data_note.md and make every line trace to the note or to a decision you can defend. Where the note gives no unit (metabolic rate), write <unit>, not a guess: Block 10 relies on it. Commit in the Git pane.

You are done when docs/codebook.csv is committed, with every rule traceable to the note or to your own decision.

If it goes wrong: if you are short of time, copy the codebook below into docs/codebook.csv and commit it; it is what most groups converge on.

column,type,rule,min,max,missing_codes,unit,source
subject_id,character,"pattern ^V[0-9]{3}$; unique; pad digits to three",,,,,data note
sex,character,"allowed M, F; recode male to M, female to F",,,,,data note
treatment_arm,character,"allowed Control, Low_dose, High_dose; match case-insensitively",,,,,data note

metabolic_rate_post,double,,5,30,-1,<unit>,data note (range from equipment)

Step 3: Clean with one command

The skill holds the procedure; your codebook holds the facts. It ships with the template and runs only when you invoke it by name.

NoteWhat the skill tells the agent (clean-with-codebook/SKILL.md) 
---
name: clean-with-codebook
description: >-
  Writes or revises a reproducible R cleaning script that applies a
  human-authored codebook (docs/codebook.csv) to raw tabular data. Use when
  asked to clean, recode or prepare raw data in a project that has a codebook.
  Not for exploratory analysis or modelling.
disable-model-invocation: true
---

# Clean data against a codebook

## Hard constraints
1. Never modify anything under data/raw/. Read raw files with explicit
   column types.
2. The codebook is the only source of rules. Do not infer units, ranges,
   missing-value codes or label mappings that the codebook does not state.
3. Do not edit docs/, scripts/functions/, scripts/02_validate.R,
   scripts/03_audit_cleaning.R or anything under tests/. If a check fails,
   report it; never change a check to make it pass.
4. Never drop a row silently. Every excluded row goes in the exclusion log
   with a reason.
5. Every changed cell goes in the cleaning log.
6. A value outside a codebook range that no codebook rule explains is set to
   NA, logged with rule "out_of_range_query", and listed in the final report.
   Never correct it by guessing a unit or decimal error.
7. No imputation.
8. Tidyverse style, native pipe, here::here() for all paths.

## Procedure
1. Present a plan before writing anything: every rule you will apply, the
   codebook row it comes from, and the order. Wait for the user to confirm.
2. If the data contain a value the codebook does not cover, stop and ask.
3. Write scripts/01_clean.R. It reads docs/codebook.csv when it runs; do not
   copy rules into the script by hand. Run it in a fresh R session
   (Rscript scripts/01_clean.R), then run it a second time and confirm the
   outputs are identical.
4. Run scripts/02_validate.R (raw data should fail, clean data should pass)
   and every test: Rscript -e "testthat::test_dir('tests')". Report both
   outputs verbatim, including skips.

## Outputs (exact columns)
- data/derived/voles_clean.csv: raw_row, then the codebook columns. raw_row
  is the 1-based row number in the raw file, not counting the header.
- data/derived/exclusion_log.csv: raw_row, subject_id (as it appears in the
  raw file), reason.
- data/derived/cleaning_log.csv: raw_row, subject_id, column, old_value,
  new_value, rule.
- rule is one of: missing_code, label_recode, id_format, out_of_range_query.

## Final report
Row counts in, out and excluded; every value set to NA for query; any gaps
in the codebook you found.

Plan, review, then execute (15 minutes)

Start: the codebook committed and the Git pane showing no changed files.

1. Invoke the skill.

Prompt (Claude Code):

/clean-with-codebook Clean data/raw/voles_raw.csv using docs/codebook.csv.

2. Review its plan before approving. Check that:

  • every rule cites a codebook row;
  • out-of-range values are set to NA and queried, not “corrected”;
  • no file outside scripts/01_clean.R and data/derived/ will be written;
  • duplicates are handled by a stated rule, with each exclusion logged.

3. Approve, then read each request. Choose Yes, manually approve edits. Watch the Git pane: new files should appear only in scripts/ and data/derived/. The skill runs the script twice, then the validation and the tests, and reports the output.

TipUsing Posit Assistant

You are done when data/derived/ contains voles_clean.csv, cleaning_log.csv and exclusion_log.csv, and the agent has reported the validation and test output.

If it goes wrong: if it stalls, loops or writes elsewhere, press Ctrl+C, Revert in the Git pane, and switch to block7-done (a working 01_clean.R and its outputs).

Step 4: One check, in a fresh R session

The agent says its tests pass: that is a claim. One command, in a fresh R sessionAn R session with nothing loaded from earlier work: Session > Restart R in RStudio or Positron (with “never save .RData” set, as on Day 1), callr::rscript() from the console, or Rscript in the terminal. Code that only works in your current session depends on something you did not record., turns it into evidence.

Run the checks (7 minutes)

1. Run every test. Restart R (Session → Restart R), then:

In the R console:

callr::r(\(d) testthat::test_dir(d), list(here::here("tests")))

What a pass proves:

Tests A pass proves
raw data are unchanged The raw file still matches its checksum: nothing changed it, by any route
every raw row is in the clean data or the exclusion log No row was dropped silently
the four log tests (old values, new values, every changed cell, agreed rule names) Every change is recorded, truthfully
each excluded subject_id is the one in the raw file Exclusions refer to real rows
no more values set to NA than the codebook explains; clean data pass every codebook rule Nothing was over-cleaned, and the result obeys your codebook
cleaning is reproducible A fresh run writes byte-identical files

2. Read the change. In the Git pane, Diff scripts/01_clean.R for anything the plan did not mention, then commit the script and its outputs.

You are done when every cleaning test passes (other blocks’ tests may skip) and the work is committed.

If it goes wrong: a failing test names the problem. Ask the agent to fix 01_clean.R, quoting the test; never the test itself (it is deny-protected). Short of time? Switch to block7-done.

# tests/test_cleaning.R ----
# Block 7: the raw data are untouched, every row is accounted for, and the
# clean data pass every codebook rule.
library(testthat)
testthat::local_edition(3)
source(here::here("scripts", "functions", "validate_voles.R"))

read_chr <- function(...) {
  readr::read_csv(
    here::here(...),
    col_types = readr::cols(.default = readr::col_character())
  )
}

clean_path <- here::here("data", "derived", "voles_clean.csv")

test_that("raw data are unchanged", {
  checksum_path <- here::here("tests", "fixtures", "raw_checksum.txt")
  skip_if_not(file.exists(checksum_path), "Block 7 Step 0 not done yet")
  recorded <- readLines(checksum_path)
  current <- unname(tools::md5sum(here::here("data", "raw", "voles_raw.csv")))
  expect_identical(current, recorded)
})

test_that("every raw row is either in the clean data or in the exclusion log", {
  skip_if_not(file.exists(clean_path), "Block 7 not done yet: no clean data")
  raw_df <- read_chr("data", "raw", "voles_raw.csv")
  clean_df <- read_chr("data", "derived", "voles_clean.csv")
  excluded_df <- read_chr("data", "derived", "exclusion_log.csv")

  expect_equal(nrow(raw_df), nrow(clean_df) + nrow(excluded_df))
  expect_setequal(
    c(clean_df$raw_row, excluded_df$raw_row),
    as.character(seq_len(nrow(raw_df)))
  )
  expect_false(any(is.na(excluded_df$reason) | excluded_df$reason == ""))
})

test_that("cleaning is reproducible: a fresh run writes identical files", {
  skip_if_not(file.exists(clean_path), "Block 7 not done yet: no clean data")
  derived <- here::here("data", "derived",
                        c("voles_clean.csv", "cleaning_log.csv", "exclusion_log.csv"))
  before <- unname(tools::md5sum(derived))
  callr::rscript(here::here("scripts", "01_clean.R"), wd = here::here(),
                 show = FALSE)
  expect_identical(unname(tools::md5sum(derived)), before)
})

test_that("clean data pass every codebook rule", {
  skip_if_not(file.exists(clean_path), "Block 7 not done yet: no clean data")
  clean_df <- readr::read_csv(clean_path, col_types = voles_col_types())
  expect_equal(nrow(readr::problems(clean_df)), 0)
  validation <- validate_voles(clean_df, "Clean data")
  expect_true(pointblank::all_passed(validation))
})
# tests/test_audit.R ----
# Block 7: the cleaning log is truthful and complete, and the cleaning did no
# more than the codebook allows. Raw values are read as text, exactly as
# entered, so a logged old value can be compared character for character.
library(testthat)
testthat::local_edition(3)

log_path <- here::here("data", "derived", "cleaning_log.csv")

allowed_rules <- c("missing_code", "label_recode", "id_format", "out_of_range_query")

read_chr <- function(...) {
  readr::read_csv(
    here::here(...),
    col_types = readr::cols(.default = readr::col_character())
  )
}

to_long <- function(data, value_name) {
  data |>
    tidyr::pivot_longer(-raw_row, names_to = "column", values_to = value_name)
}

same <- function(x, y) (is.na(x) & is.na(y)) | (!is.na(x) & !is.na(y) & x == y)

audit_inputs <- function() {
  raw_df <- read_chr("data", "raw", "voles_raw.csv") |>
    dplyr::mutate(raw_row = as.character(dplyr::row_number()))
  clean_df <- read_chr("data", "derived", "voles_clean.csv")
  log_df <- read_chr("data", "derived", "cleaning_log.csv")
  list(
    raw = raw_df,
    clean = clean_df,
    log = log_df,
    raw_long = to_long(raw_df, "raw_value"),
    clean_long = to_long(clean_df, "clean_value")
  )
}

test_that("every logged old value matches the raw file", {
  skip_if_not(file.exists(log_path), "Block 7 not done yet: no cleaning log")
  x <- audit_inputs()
  untruthful <- x$log |>
    dplyr::left_join(x$raw_long, by = c("raw_row", "column")) |>
    dplyr::filter(!same(old_value, raw_value))
  expect_equal(nrow(untruthful), 0)
})

test_that("every logged new value is the value in the clean file", {
  skip_if_not(file.exists(log_path), "Block 7 not done yet: no cleaning log")
  x <- audit_inputs()
  mismatched <- x$log |>
    dplyr::inner_join(x$clean_long, by = c("raw_row", "column")) |>
    dplyr::filter(!same(new_value, clean_value))
  expect_equal(nrow(mismatched), 0)
})

test_that("every changed cell appears in the log", {
  skip_if_not(file.exists(log_path), "Block 7 not done yet: no cleaning log")
  x <- audit_inputs()
  numeric_cols <- c("mass_pre_g", "mass_post_g", "metabolic_rate_post")
  changed <- x$clean_long |>
    dplyr::left_join(x$raw_long, by = c("raw_row", "column")) |>
    dplyr::mutate(
      # numbers are compared as numbers, so 28.30 and 28.3 count as unchanged
      differs = dplyr::if_else(
        column %in% numeric_cols,
        !same(suppressWarnings(as.numeric(clean_value)),
              suppressWarnings(as.numeric(raw_value))),
        !same(clean_value, raw_value)
      )
    ) |>
    dplyr::filter(differs)
  unlogged <- dplyr::anti_join(changed, x$log, by = c("raw_row", "column"))
  expect_equal(nrow(unlogged), 0)
})

test_that("every cleaning-log rule comes from the agreed list", {
  skip_if_not(file.exists(log_path), "Block 7 not done yet: no cleaning log")
  rules <- unique(audit_inputs()$log$rule)
  expect_true(all(rules %in% allowed_rules),
              label = paste("unexpected rule(s):",
                            paste(setdiff(rules, allowed_rules), collapse = ", ")))
})

test_that("each excluded row's subject_id is the one in the raw file", {
  skip_if_not(file.exists(log_path), "Block 7 not done yet: no cleaning log")
  x <- audit_inputs()
  excluded <- read_chr("data", "derived", "exclusion_log.csv") |>
    dplyr::left_join(dplyr::select(x$raw, raw_row, raw_id = subject_id),
                     by = "raw_row")
  expect_true(all(same(excluded$subject_id, excluded$raw_id)))
})

test_that("no more values were set to NA than the codebook explains", {
  skip_if_not(file.exists(log_path), "Block 7 not done yet: no cleaning log")
  x <- audit_inputs()
  codebook <- read_chr("docs", "codebook.csv")
  numeric_rules <- dplyr::filter(codebook, !is.na(min) | !is.na(max) | !is.na(missing_codes))

  for (i in seq_len(nrow(numeric_rules))) {
    col <- numeric_rules$column[[i]]
    codes <- trimws(strsplit(dplyr::coalesce(numeric_rules$missing_codes[[i]], ""), ";")[[1]])
    lo <- as.numeric(numeric_rules$min[[i]])
    hi <- as.numeric(numeric_rules$max[[i]])

    kept_raw <- x$raw[[col]][match(x$clean$raw_row, x$raw$raw_row)]
    value <- suppressWarnings(as.numeric(kept_raw))
    explained <- !is.na(kept_raw) & (
      kept_raw %in% codes |
        (!is.na(lo) & !is.na(value) & value < lo) |
        (!is.na(hi) & !is.na(value) & value > hi)
    )
    newly_na <- !is.na(kept_raw) & is.na(x$clean[[col]])

    expect_equal(sum(newly_na), sum(explained),
                 label = paste("values newly set to NA in", col))
  }
})

The validation rules

scripts/functions/validate_voles.R was transcribed from the codebook by a person, not by the agent that writes the cleaning script. It uses the pointblank package: each line is one rule, and interrogate() reports how many rows break it. (pointblank calls the object that holds the rules an “agent”; it has nothing to do with AI agents.)

# scripts/functions/validate_voles.R ----
# Rules transcribed from docs/codebook.csv by a human, not by the agent
# that writes the cleaning script.

voles_col_types <- function() {
  readr::cols(
    subject_id = readr::col_character(),
    sex = readr::col_character(),
    treatment_arm = readr::col_character(),
    mass_pre_g = readr::col_double(),
    mass_post_g = readr::col_double(),
    metabolic_rate_post = readr::col_double(),
    .default = readr::col_character()
  )
}

validate_voles <- function(data, label) {
  data |>
    pointblank::create_agent(label = label) |>
    pointblank::col_vals_not_null(columns = c(subject_id, sex, treatment_arm)) |>
    pointblank::col_vals_regex(columns = subject_id, regex = "^V[0-9]{3}$") |>
    pointblank::rows_distinct(columns = subject_id) |>
    pointblank::col_vals_in_set(columns = sex, set = c("M", "F")) |>
    pointblank::col_vals_in_set(
      columns = treatment_arm,
      set = c("Control", "Low_dose", "High_dose")
    ) |>
    pointblank::col_vals_between(
      columns = c(mass_pre_g, mass_post_g),
      left = 15, right = 60, na_pass = TRUE
    ) |>
    pointblank::col_vals_between(
      columns = metabolic_rate_post,
      left = 5, right = 30, na_pass = TRUE
    ) |>
    pointblank::interrogate()
}

scripts/02_validate.R runs the rules on the raw data, which should fail (for example Raw data (expected to FAIL): 7 of 10 rules fail), and, once the cleaning has run, on the clean data, which should pass. It also lists any value that could not be read as a number: such a value would become NA and slip past the range rules. In an interactive session it opens the full report in the Viewer.

In the R console:

source(here::here("scripts", "02_validate.R"))
# scripts/02_validate.R ----
# Runs the codebook rules on the raw data (expected to FAIL) and, once
# 01_clean.R has run, on the clean data (expected to PASS). In an interactive
# session the full pointblank report also opens in the Viewer.
library(tidyverse)
library(here)
source(here("scripts", "functions", "validate_voles.R"))

report_validation <- function(validation) {
  steps <- validation$validation_set
  n_failed <- sum(!steps$all_passed)
  cat(
    validation$label, ": ",
    if (n_failed == 0) "all rules pass" else paste(n_failed, "of", nrow(steps), "rules fail"),
    "\n",
    sep = ""
  )
  if (interactive()) print(validation)
  invisible(validation)
}

raw_df <- read_csv(here("data", "raw", "voles_raw.csv"), col_types = voles_col_types())
# values that could not be read as numbers become NA and would pass the
# range rules, so list them
print(problems(raw_df), width = Inf)
report_validation(validate_voles(raw_df, "Raw data (expected to FAIL)"))

clean_path <- here("data", "derived", "voles_clean.csv")
if (file.exists(clean_path)) {
  clean_df <- read_csv(clean_path, col_types = voles_col_types())
  report_validation(validate_voles(clean_df, "Clean data (expected to PASS)"))
}
Warning

na_pass = TRUE lets genuine missing values through. It would also let through a cleaning script that replaced every mass with NA. Validation alone cannot catch over-cleaning; tests/test_audit.R can.

Read the log yourself

Tests check consistency; they cannot tell you whether a change was the right decision. The shipped audit script shows what kinds of change were made and samples ten logged changes for you to check by eye against the raw file (View(), or Positron’s Data Explorer).

source(here::here("scripts", "03_audit_cleaning.R"))
# scripts/03_audit_cleaning.R ----
library(tidyverse)
library(here)
source(here("scripts", "functions", "validate_voles.R"))

to_long <- function(data, value_name) {
  data |>
    pivot_longer(
      -raw_row,
      names_to = "column",
      values_to = value_name,
      values_transform = as.character
    )
}

# raw values are read as text, exactly as entered, so a logged old value can be
# compared character for character
raw_long_df <- read_csv(
  here("data", "raw", "voles_raw.csv"),
  col_types = cols(.default = col_character())
) |>
  mutate(raw_row = as.character(row_number())) |>
  to_long("raw_value")

clean_long_df <- read_csv(here("data", "derived", "voles_clean.csv"), col_types = voles_col_types()) |>
  to_long("clean_value")

cleaning_log_df <- read_csv(
  here("data", "derived", "cleaning_log.csv"),
  col_types = cols(.default = col_character())
)

# 1. Truthful: every logged old value matches the raw file ----
untruthful_df <- cleaning_log_df |>
  left_join(raw_long_df, by = c("raw_row", "column")) |>
  filter(!map2_lgl(old_value, raw_value, identical))

# 2. Complete: every changed cell appears in the log ----
unlogged_df <- clean_long_df |>
  left_join(raw_long_df, by = c("raw_row", "column")) |>
  filter(!map2_lgl(clean_value, raw_value, identical)) |>
  anti_join(cleaning_log_df, by = c("raw_row", "column"))

# both tables should have no rows; tests/test_audit.R checks the same things
# and fails if they do not
print(untruthful_df, width = Inf)
print(unlogged_df, width = Inf)

# 3. What kinds of change were made ----
cleaning_log_df |> count(column, rule, sort = TRUE)

# 4. Ten logged changes to check by hand against the raw file ----
set.seed(2026)
cleaning_log_df |> slice_sample(n = 10) |> print(width = Inf)

How the template’s safeguards were made

The checksum. The template’s tests/fixtures/raw_checksum.txt was written once, from the shipped raw file, like this:

fs::dir_create(here::here("tests", "fixtures"))
writeLines(
  unname(tools::md5sum(here::here("data", "raw", "voles_raw.csv"))),
  here::here("tests", "fixtures", "raw_checksum.txt")
)

Do the same for your own raw data, then commit it. The template’s .gitattributes contains data/raw/** -text, so git does not convert line endings, which would change the checksum on Windows.

The deny rules. This is the .claude/settings.json in your workshop repository, the same file you read in Block 6:

{
  "permissions": {
    "defaultMode": "default",
    "deny": [
      "Edit(/data/raw/**)",
      "Read(/docs/data_note.md)",
      "Edit(/docs/data_note.md)",
      "Edit(/docs/codebook.csv)",
      "Edit(/scripts/02_validate.R)",
      "Edit(/scripts/03_audit_cleaning.R)",
      "Edit(/scripts/functions/validate_voles.R)",
      "Edit(/tests/fixtures/**)",
      "Edit(/tests/make_reference.R)",
      "Edit(/tests/test_cleaning.R)",
      "Edit(/tests/test_audit.R)",
      "Edit(/renv.lock)",
      "Edit(/.github/**)",
      "Edit(/.claude/**)",
      "Edit(/.posit/**)",
      "Edit(/hooks/**)",
      "Read(/.Renviron)",
      "Read(/.env)"
    ]
  }
}

A leading / anchors each pattern to the project root. The rules protect specific files rather than whole folders, so the agent can still write scripts/01_clean.R and data/derived/. To protect files of your own, add rules with /permissions. Posit Assistant has no documented path rules for file edits; use the guard hook from the Going further section of Block 6 instead.

Warning

What each control covers. The deny rule blocks the agent’s file-editing tools, and shell output redirects such as > file. It does not cover R code the agent runs: an R script that writes to data/raw/ is a different route. The checksum test catches a change made by any route, but only after the fact. Use both: one prevents, the other detects. A deny rule on reading does not stop data reaching the model provider by other routes; see Block 4.

The skill. The skill ships in .agents/skills/ and .claude/skills/. To use it in another project, download it and unzip it into that project’s .agents/skills/ (unzip(file.choose(), exdir = here::here(".agents", "skills"))), then copy the folder into .claude/skills/ with fs::dir_copy().

Glossary

term definition
checksum A short fingerprint computed from a file's contents, for example with tools::md5sum(). Any change to the file changes the checksum, so it detects changes made by any route.
codebook A table describing each variable: its type, valid range, missing-value codes, unit and label mappings. It is the data dictionary from Day 2 with machine-readable rules, and you own it, not the AI.
deny rule A permission rule in the deny list of .claude/settings.json that stops Claude Code's built-in tools from editing or reading the matching files. It checks shell output redirects such as > file, but not R code or most other commands that change the same files.
fresh R session An R session with nothing loaded from earlier work: Session > Restart R in RStudio or Positron (with "never save .RData" set, as on Day 1), callr::rscript() from the console, or Rscript in the terminal. Code that only works in your current session depends on something you did not record.
lockfile The renv.lock file that records the R version and the exact package versions a project uses, so renv::restore() can rebuild the same environment.
sentinel value A number with a special meaning, such as 9999 for "not recorded" or -1 for "run failed". It must be documented in a codebook and recoded before analysis.
