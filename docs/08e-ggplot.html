Block 5: Saving figures correctly

The on-screen plot pane is rarely the same physical size as the saved figure. A font that looks correct at 10pt in the RStudio plot pane can look quite different in the saved PDF, because the plot pane is sized to your window, not to the saved file, while the PDF is drawn at the dimensions you specify. This is the single most common source of “the figure looks fine on my screen but is unreadable in the manuscript” problems.

Two extensions and one habit solve this.

ggview for canvas-size preview

ggview (Domin, 2025) adds a canvas() layer to the plot. The preview then renders at the dimensions the file will be saved at, so what you see is what you save.

fig <- penguins_complete |> 
  ggplot(aes(x = species, y = body_mass_g, fill = species)) +
  ggdist::stat_halfeye(adjust = 0.5, justification = -0.2,
                       .width = 0, point_colour = NA, alpha = 0.8) +
  geom_boxplot(width = 0.12, outlier.shape = NA, alpha = 0.5) +
  colorspace::scale_fill_discrete_qualitative(palette = "Dark2") +
  labs(x = NULL, y = "Body mass (g)") +
  theme_minimal(base_size = 12) +
  theme(legend.position = "none") +
  ggview::canvas(width = 7, height = 5, units = "in", dpi = 300)

# Print displays the figure at the canvas size
print(fig)

# save_ggplot uses the canvas dimensions
ggview::save_ggplot(
  fig,
  here::here("outputs", "figures", "fig01_body_mass.png")
)

For one-off iteration, canvas() is lighter than the older camcorder package, which auto-saves every plot to disk. Use camcorder only when you specifically want a session-wide recording or a GIF of your iteration history.

The ragg graphics device

ggsave() is the interface for writing figures; under the hood it calls a graphics device to do the rendering. For raster output (PNG, JPG, TIFF), ragg::agg_png is the modern recommended device because it renders text with better antialiasing and accesses system fonts without extrafont or showtext. (If you track figures in git, note that a PDF changes on every save, because it embeds a creation date.)

To set ragg as the plot pane backend in RStudio (≥1.4), go to Tools → Global Options → General → Graphics → Backend: AGG. For Quarto documents, set knitr::opts_chunk$set(dev = "ragg_png") in the setup chunk.

The two-format default

Save publication figures in two formats:

  • PDF for inclusion in LaTeX manuscripts and final journal submission. A vector format that scales to any size, and the default for serious typesetting.
  • PNG at 300 dpi via ragg::agg_png for slides, posters, and quick previews.
ggplot2::ggsave(
  filename = here::here("outputs", "figures", "fig01_body_mass.pdf"),
  plot = fig,
  width = 7,
  height = 5,
  units = "in"
)

ggplot2::ggsave(
  filename = here::here("outputs", "figures", "fig01_body_mass.png"),
  plot = fig,
  width = 7,
  height = 5,
  units = "in",
  dpi = 300,
  device = ragg::agg_png,
  bg = "white"
)

bg = "white" is a safe default for PNG output. Without it, ggsave() takes the background from the theme’s plot.background, so bg = "white" guards against themes with a blank background, such as ThemePark or custom themes. Those would otherwise give a transparent PNG, which displays badly in many viewers.

Warning

Always specify width, height, units, and dpi explicitly. Never rely on ggsave() defaults. The defaults rarely match the dimensions of the figure you actually want.

Quick save: same plot, two sizes (3 minutes)

Run this in your own RStudio. It saves the same plot twice: once at full-page width, and once at half the width and height, the size of a single journal column.

quick <- penguins_complete |>
  ggplot(aes(flipper_length_mm, body_mass_g, colour = species)) +
  geom_point() +
  labs(x = "Flipper length (mm)", y = "Body mass (g)", colour = "Species") +
  theme_minimal(base_size = 12)

dir.create(here::here("outputs", "figures"), recursive = TRUE, showWarnings = FALSE)

ggsave(here::here("outputs", "figures", "quick_big.png"), quick,
       width = 7, height = 5, units = "in", dpi = 300,
       device = ragg::agg_png, bg = "white")

ggsave(here::here("outputs", "figures", "quick_small.png"), quick,
       width = 3.5, height = 2.5, units = "in", dpi = 300,
       device = ragg::agg_png, bg = "white")

Before you open the files, predict in the chat: in the small version, will the text look bigger or smaller compared with the plot?

Then open both files (from the Files pane) and check. What went wrong in the small one, and which single argument would you change to fix it?

The text is the same 12 pt in both files, but the small figure has half the room, so the text takes up far more of it. The legend squeezes the panel and the x-axis labels run into each other. You could fix it by lowering base_size (for example to 8), by moving the legend to the bottom, or, better, by deciding the final size first and designing the figure at that size. ggview::canvas() lets you do exactly that.

Note

Interactive figures (the ggiraph examples from Blocks 2 and 4) are web pages, not images, so ggsave() cannot write them. Save them as HTML with htmlwidgets::saveWidget(girafe(ggobj = fig), "fig.html"), and always save a static PDF/PNG of the same plot as well, for the manuscript.
